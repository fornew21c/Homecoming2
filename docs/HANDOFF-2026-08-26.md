## 오늘 한 일

### 지하철 구간을 실제 노선 모양으로 그린다 — 1,998m → 64m

**이번 세션의 본체다.** 설계문서와 계획이 따로 있다:
[설계](superpowers/specs/2026-08-26-subway-polyline-design.md) ·
[계획](superpowers/plans/2026-08-26-subway-polyline.md).

지하철 구간은 두 역 좌표를 잇는 직선이었다. 실제 선로는 직선이 아니라서 서강대 →
풍산에서 저장된 선이 실제 노선에서 **1,994m**(능곡역) 벌어졌다. 이탈 문턱이
1,000m 라 정상 귀가가 이탈로 판정됐다.

이제 사이 역들을 거치는 꺾은선이다.

```
서강대 → 홍대입구 → 가좌 → DMC → 수색 → 한국항공대 → 강매 → 행신 → 능곡 → 곡산 → 백마 → 풍산
```

시뮬레이터에서 경로를 다시 만들어 쟀다 — **실제 역들이 저장된 선에서 최대 64m.**
직선이었다면 1,998m. 문턱을 건드릴 이유가 없어졌다.

자료는 [전국도시철도역사정보표준데이터](https://www.data.go.kr/data/15013205/standard.do)
다. **무료 · 키 불필요.** 받는 주소는 이것이고, 상세 페이지의 버튼이 가리키는 값이다.

```
https://data.kric.go.kr/rips/dataset/download.file?type=filedata&id=32&operation=1
```

`python3 Tools/subway-lines.py <내려받은.xlsx>` 가 `Server/data/subway-lines.json` 을
굽는다(노선 46개 · 역 1,099개 · 116KB). 서버가 `GET /subway/leg?from=&to=` 로 준다 —
`GET /bus/leg` 옆자리, 같은 계약이다(빈 결과는 실패가 아니다).

### 지도를 키우고 카드 위로 올렸다

높이 335 → **525pt**(보이는 높이의 46% → 72%), 그리고 **지도가 카드 위**다.

키우기만 해서는 소용이 없었다. 카드가 정류장 10개짜리 노선도 때문에 450pt 를 먹어서
지도가 화면 606pt 에서 시작했고, 화면이 874pt 니 스크롤 안 하면 **268pt 만** 보였다.
하필 귀가자 마커가 그 잘린 띠에 들어간다 — `region()` 이 bbox × 1.25 라 귀가자는
언제나 가장자리에서 10% 안쪽인데, 335pt 지도에서 33pt 다. 화면 밖 68pt 보다 작다.

**지도를 열었는데 사람이 안 보였다.** 8/25 실행에서 위치 보고 103건 중 103건이 그랬다.

노선도를 접는 길도 있었지만 그건 다 보여야 한다고 정했다. 그래서 순서를 바꿨다.

### 8/25 사건 — 가족이 도착한 줄 알았다

로그를 되짚어 셋을 갈랐다.

**서버는 도착을 보낸 적이 없다.** 18:30 에도 `moving · 3126m` 을 밀고 있었고 실제
도착은 18:48:39 다. 화면이 그렇게 읽히게 쓰여 있었다 — 카드가 `18:30 도착` 이라고만
적었다. 도착 **예정** 시각인데 "18:30에 도착했다" 로 읽힌다.

`arrivalClockLine` 하나로 모아 카드·잠금화면·아일랜드가 같이 쓴다. **도착한 뒤에는
`예정` 을 뗀다** — 그때는 실제로 닿은 시각이다.

**왜 하필 18:30 이었나.** 18:09:38 에 경로 이탈(1,105m)로 직선거리 추정으로 넘어가며
남은거리가 11,668m → 8,251m 로 한 번에 줄었고 도착예정도 당겨졌다. 복귀 로그가
없으니 도착까지 39분을 그 추정으로 돌았다.

```
저장된 경로의 예정   18:54   ← 실제 18:48:39 과 6분 차이
직선 폴백의 예정     ~18:30  ← 18분 차이
```

**경로 추정이 더 정확했다.** 도착예정은 `총소요시간 + 지연 − 경과시간` 이라 위치를
아예 안 쓰는데, 위치가 벗어났다고 그 계산까지 버린 것이다. 이제 이탈해도 도착예정은
경로에서 낸다. **남은거리는 그대로 직선이다** — 시간은 경과로 알 수 있지만 자리는
알 수 없다.

### 위치 보고 응답으로 상태를 받는다

저장된 경로로 도는 귀가에서 남은거리·진행도의 주인은 서버다. 앱은 좌표만 자기 GPS 로
쓰고 나머지는 nil 로 비운다(`pushUpdate` 의 `onRoute ? nil : meters`). 그래서 푸시가
늦으면 **한 화면 안에서 어긋났다** — 8/21 14:41 캡처가 그 상태였다(화면 3.2km, 그때
서버 2,093m).

`POST /session/{id}/location` 응답에 `content_state` 를 실었다. 이미 오가는 요청이라
새 엔드포인트도 추가 요청도 없다. 앱은 `HomecomingActivityManager.adopt(_:)` 로 받되
**앱만 아는 둘(`checkInDeadline` · `anomaly`)은 지킨다** — 서버는 그 둘을 모른다.

검증: 시뮬레이터는 갱신 토큰을 못 받고 로컬 서버는 APNs 가 꺼져 있다. **푸시가 한 건도
없는 환경**인데 카드가 27.2km → 22.5km 로 따라왔다(그때 서버 값 22,544m).

### 그 밖

**안전귀가 모드를 화면에 되돌렸다.** `settingsTab` 에서 빠져 있는 동안 `safetyMode` 가
`UserDefaults` 기본값 `false` 에 고정이라 **지연·정지·무응답 감시가 전부 꺼져 있었다.**
켜는 길이 런치 인자뿐이었다. 참고로 **이탈은 이 토글과 무관하다** — `SafetyWatch` 는
셋만 만들고 이탈은 서버가 판정한다.

**버스 시군구 35개를 `BUS_SGG` 에 넣었다**(성남 포함, 22개 시). 넣기 전에 경유정류장
API 로 다시 확인했다 — `getBusStop` 에 코드가 있다는 게 그 API 에서도 된다는 뜻이
아니다. 그러다 **구멍을 찾았다**: 노선이 표 밖으로 나가면 정류장이 뭉텅 빠진 채 온다
(3500번은 `sttn_seq` 0~82 중 37자리가 빈다). 그대로 이으면 빠진 구간을 가로지르는
직선이 되고 화면은 그걸 실제 노선인 것처럼 그린다. 이제 이어지는지 검사한다.

**조사를 받침에 맞춘다.** `아빠이` → `아빠가`. 서버 4곳 · 앱 2곳이 같은 규칙을 쓴다.

**`content-state` 표에 빠져 있던 좌표 다섯을 문서에 적었다**(`lat`·`lon`·`homeLat`·
`homeLon`·`homeRadius`).

## 오늘 새로 알게 된 함정

**XLSX 는 빈 칸을 아예 안 적는다.** 셀을 나온 순서대로 세면 열이 밀린다. 그렇게 읽고
"좌표 없는 행이 661개" 라는 값을 얻었는데 실제로는 **하나도 없었다.** 셀 주소로 읽는다.

**역번호는 노선 전체가 아니라 블록 안에서만 순서다.** 경의중앙선을 역번호로 세우면
지선(서울역·신촌)과 옛 코드 블록 때문에 되돌아간다(비 1.417). 한 구간은 한 블록
안이라 서강대(1263) → 풍산(1274)은 깨끗하다. 그래서 검증을 노선이 아니라 **구간**
단위로 한다.

**되돌아감 비만으로는 블록 점프를 못 잡는다.** 건너뛴 방향이 가려는 방향과 같으면
비가 안 커진다 — 지평 → 서울역 → 신촌은 58km 를 건너뛰는데 비가 1.02 다. **시험이
잡아냈다.** 그래서 이웃 간격도 본다(15km, 실측 분포에서 골랐다: 중앙값 1,093m ·
95% 5,618m, 정상인데 긴 구간은 인천공항선 10.1km · 동해선 13.6km).

**역 이름은 양쪽으로 포함 검사를 해야 한다.** 경로에 적힌 이름이 `서강대학교` 인데
자료는 `서강대역` 이라, 한 방향만 보면 못 찾는다. 실제로 첫 시도에서 지하철 구간이
**조용히 직선으로 저장됐다.** 반대 방향은 헐거우니 **가장 긴 것**을 고른다
(`서울대입구` 안에 `서울` 이 있다).

**로컬 서버는 공공데이터를 못 부를 때가 있다.** 사내망 TLS 다 —
`CERTIFICATE_VERIFY_FAILED: self-signed certificate`. 한도(`429`)가 아니다. 서버의
HTTP 호출이 `Tools/hc_tls.py` 를 안 쓴다. 그때는 버스 구간이 자동차 폴백이 된다.
**배포 서버는 정상이다.** (지하철은 표를 들고 있어서 이 영향을 안 받는다.)

**`xcrun simctl launch` 가 인자를 씹는 것을 이번에도 봤다.** `-homecomingBackend` 가
빠져 배포 서버(HTTPS)로 붙어 TLS 오류가 났다. 재시도 루프로 감싼다.

**서버 시험을 `cd Server` 에서 돌리면 `Server/Server/` 가 생긴다.** DB 경로가 cwd
기준이라 그렇다. `.gitignore` 에 넣어 뒀다.

굳는다는 가설은 죽었다 — 갱신 103건 전부에서 다시 잡혔고 매번 귀가자를 담았다.

시작하는 문제(위 참고)가 그 정체일 가능성이 크지만 **단정할 수 없다.**
