# 공공데이터 버스 API — 무엇이 되고 무엇이 안 되나

경로를 만들 때 정류장 좌표를 정확히 얻으려고 붙였다. 알아낸 것을 남긴다 —
이 API 들은 문서만 봐서는 무엇이 오는지 알 수 없고, 오류 메시지도 오해를 부른다.

## 오류 코드 읽는 법

이게 제일 중요하다. **키가 틀린 것처럼 보이는데 아닌 경우가 대부분이다.**

| 코드 | 뜻 | 실제로 해야 할 일 |
|---|---|---|
| `12` `NO_OPENAPI_SERVICE` | 그 경로가 없다 | 서비스명·오퍼레이션명을 고친다 |
| `30` `SERVICE_KEY_IS_NOT_REGISTERED` | **경로는 있는데 이 키에 권한이 없다** | 그 API 를 활용신청한다. 키는 멀쩡하다 |
| `50` `NO_DATA_FOUND` | 조건에 맞는 게 없다 | 파라미터 값을 본다 |
| `51` `INVALID_PARAMETER` | 값이 틀렸다 | 아래 "함정" 을 본다 |
| `52` `MISSING_REQUIRED_PARAMETER` | 필수가 빠졌다 | 아래 표를 본다 |

30 을 "키가 잘못됐다" 로 읽고 몇 시간을 흘려보냈다. 12 와 30 이 갈린다는 걸
알아채고 나서야 경로 문제라는 게 드러났다.

## 함정

**신규 계열에 `_type=json` / `type=json` 을 붙이면 51 이다.** JSON 이 기본이고
그 파라미터를 거부한다. 다른 공공데이터 API 는 대부분 요구하는 값이라 습관적으로
붙게 된다. 구형 계열은 반대로 `_type=json` 을 받는다.

**계열마다 도시코드 체계가 다르다.** 신규는 행정표준코드(서울 `11`, 경기 `41`),
구형 TAGO 는 자체 코드(고양시 `31100`). 섞으면 50 이 온다.

## 계열 두 가지

### 신규 (2025 개편) — `국토교통부_버스노선` / `국토교통부_버스정류장`

```
https://apis.data.go.kr/1613000/BusRoute/getBusRoute
  필수  opr_ymd(운영일자) + ctpv_cd(시도)
  응답  rte_id, rte_no, rte_nm, dptre_sttn_nm, arvl_sttn_nm

https://apis.data.go.kr/1613000/BusStop/getBusStop
  필수  opr_ymd + ctpv_cd + sgg_cd(시군구)
  응답  sttn_id, sttn_nm, sttn_ars_no, ctpv_nm, sgg_nm, emd_nm
```

**둘 다 좌표가 없다.** 노선번호로 거르는 파라미터도 없어서 그 시도를 통째로
훑어야 한다.

서울을 포함해 전국이 나온다. 정류장 이름이 대중교통 앱과 같다 —
`출발역.은행앞` 처럼 점까지 일치한다.

### 구형 (TAGO) — `BusSttnInfoInqireService`

```
https://apis.data.go.kr/1613000/BusSttnInfoInqireService/getSttnNoList
  필수  cityCode + nodeNm(정류소명)
  응답  nodenm, nodeno, gpslati, gpslong      ← 좌표가 여기 있다
```

**좌표가 있다. 그런데 서울이 없다.** 도시코드 138개에 서울이 아예 빠져 있다
(서울은 별도 TOPIS API 를 쓴다). 고양시는 `31100` 이다.

> **2026-08-27 갱신 — 이제 두 지역 다 이름으로 좌표를 얻는다.**
> 서울은 열린데이터광장 표(`seoul-stops.json`, 11,239건), 경기는 GBIS
> `getBusStationListv2`(이름만 주면 좌표까지 온다). 아래 표는 그 전 이야기다.

## 그래서 지금 얻을 수 있는 것

| | 서울 | 경기(고양) |
|---|---|---|
| 정류장 **이름** | ✅ 신규 정류장 API | ✅ |
| 정류장 **좌표** | ❌ (TOPIS 별도 신청) | ✅ 구형 TAGO |

## 좌표가 실제로 얼마나 중요한가

**생각보다 안 중요하다.** 좌표열의 용도는 "지금 어느 구간에 있나" 판정뿐이고,
이탈 판정 기준이 1km 다. MapKit 검색이 주는 값이 실측과 245m 어긋나도 묻힌다.

실제로 문제였던 건 **이름**이다. "환승로터리" 를 검색하면 근처 GS25 가 나오고,
그게 그대로 가족 잠금화면에 "GS25까지 9분" 으로 떴다. 그건 경로 만들기 화면에
이름 고치는 칸을 둬서 해결했다.

(참고 — 공식 명칭은 "신촌로**터**리" 다. 우리가 찾던 "로**타**리" 와 철자가
다르고, 애플 지도가 못 찾은 이유의 일부일 수 있다.)

## 아직 안 붙인 것

- **`BusRouteInfoInqireService/getRouteAcctoThrghSttnList`** (구형, 미신청)
  노선별 경유정류소 목록. 이게 있으면 버스 구간을 자동차 경로로 대신하지 않고
  실제 정류소를 이어 그릴 수 있다. 다만 **서울이 빠지므로 반쪽이다**
- **서울시 TOPIS** — 서울 구간의 좌표를 얻으려면 이것이 필요하다

## 노선의 경유 정류장 (2026-08-20 확인)

**승인된 서비스 이름은 `국토교통부_버스노선별 경유정류장` 이다.** 옛 TAGO 계열
(`BusRouteInfoInqireService`)은 이 키에 권한이 없다 — 403 이 온다.

```
https://apis.data.go.kr/1613000/BusRoutespecificStopInformation
                       /getBusRoutespecificStopInformation
  필수  opr_ymd + ctpv_cd + sgg_cd
  선택  rte_id                        ← 주면 그 노선만
  응답  sttn_seq, sttn_id, sttn_nm, emd_nm ...   ← 좌표는 없다
```

**문서에 없는 것 셋. 여기서 다 막혔다.**

1. **`opr_ymd` 가 최근이면 자료가 없다.** `20260601` 은 되고 `20260731` 이후는
   `NO_DATA_FOUND`(50) 다. 월 단위 스냅샷으로 보인다. 서버는 후보 날짜를
   차례로 시험해 되는 것을 캐시한다(`bus_opr_ymd`).

2. **`sgg_cd` 가 없으면 52 `MISSING_REQUIRED_PARAMETER` 다.** 그런데 그 값을
   **이 계열 안에서는** 좌표나 노선번호에서 얻지 못했다 —
   (2026-08-27 — 경기는 GBIS 가 `routeId` 하나로 답해서 이 값이 필요 없어졌다)
   - 노선표(`BusRoute`)의 `sgg_cd` 는 경기 4,671개 노선 전부 `41000`(도 단위 자리표시자)
   - 시군구 목록 API(`BusLcInfoInqireService`)는 권한 없음(403)
   - 코드 공간을 훑는 것도 못 믿는다 — 동시 요청 16개로 훑었더니 조용히 실패가
     섞여 41285 처럼 **되는 것이 결과에 안 나왔다**

   그래서 **자료가 오는 것을 확인한 코드만** `BUS_SGG` 에 적어 둔다.

   **2026-08-21 정정 — 코드를 얻는 길이 있다.** 위 `getBusStop` 응답에 `sgg_nm` 이
   온다. 즉 코드를 넣어 보면 **자료가 그게 어느 시군구인지 말해 준다.** 확인이
   짐작이 아니게 되는 지점이다. 그날 41000~41550 을 훑어 35개를 확인했다:

  수원시    41111 · 41113 · 41115 · 41117

   `41190`(부천시 통합 코드)은 자료가 없다 — 이 자료는 2016년에 폐지된 **옛 구
   코드**(원미·소사·오정)로 들고 있다. 코드가 행정구역 현황과 다를 수 있다는 뜻이다.

   **2026-08-25 — 경기는 다 훑었다.** `launchd` 가 `Tools/sgg-sweep.py` 를 예산
   700 으로 돌려 41000~41999 를 마쳤고, **41551 이상에서는 하나도 안 나왔다.**
   그래서 경기 목록은 위 35개로 끝이다(김포·화성·광주·양주·포천 등은 이 자료에 없다).

   **서울은 251개까지 확인 0개다.** 그 범위에 실제 구 코드가 들어 있는데도
   (11110 종로 · 11140 중구 · 11170 용산 · 11230 동대문) 빈 결과다 — 서울 시내버스가
   이 자료에 없다는 것과 맞는다. 남은 749개도 같을 공산이 크다.

   **`getBusStop` 에 있다고 경유정류장 API 에서도 되는 것은 아니다.** 그래서
   `BUS_SGG` 에 적기 전에 이 API 로 한 번 더 확인한다. 2026-08-25 에 성남 세 구로
   확인했다 — `41131` 위례자이 · `41133` 신흥역.종합시장 · `41135` 율동공원이 그대로
   왔다. 실제 노선으로도 봤다: 66번(`rte_id` 41255002)이 수정구 17 + 분당구 30 =
   47개로 `sttn_seq` 0~46 **빈 자리 없이** 이어졌다.

   **비용.** 코드 하나가 요청 하나다. 35개를 동시 4로 물으면 **7.6초**(요청당 평균
   0.83초, 실패 0). 경로를 만들 때만 나가고 프로세스가 사는 동안 캐시된다.

3. **한 노선의 정류장이 시군구별로 쪼개져 온다.** 999번은 일산동구 42개 ·
   덕양구 32개 · 일산서구 18개로 나뉘어 나왔다. 시군구마다 받아 `sttn_seq` 로
   합쳐야 노선 전체가 된다.

   **`BUS_SGG` 밖으로 나가는 노선은 구멍이 난 채로 온다.** 3500번(분당→서울)은
   분당구 46개만 오고 `sttn_seq` 0~82 중 **37자리가 비었다**(2026-08-25). 그대로
   이으면 빠진 구간을 가로지르는 직선이 되고, 화면은 그걸 실제 노선인 것처럼
   그린다 — 자동차 폴백보다 나쁘다(그쪽은 화면이 말이라도 해 준다). 그래서
   `bus_route_stop_names` 가 `sttn_seq` 가 이어지는지 보고, 안 이어지면 자료가
   없는 것으로 둔다.

### 일일 요청 한도 — 훑기 전에 반드시 본다

`429` + `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR`(22) = **일일 요청 제한
초과**다. 2026-08-21 에 시군구 코드 1,000개를 동시 4개로 훑다가 그 키의 하루치를
다 써서, 그 뒤 서버의 버스 노선 조회까지 종일 막혔다. 자정에 초기화된다.

훑는 작업은 이렇게 한다 —
  1. 먼저 한 번 불러 `429` 가 아닌지 본다
  2. **동시 1개, 초당 1건 이하.** 4개로도 429 가 섞였고, 그러면 되는 코드가 결과에서
     조용히 빠진다(위 2번 항목이 그렇게 틀렸다)
  3. 실패와 "자료 없음" 을 구분해서 세고, 진행분을 파일에 적어 둔다. 멈춰도 한 것이 남게
  4. 남은 코드 449개면 8분쯤 걸린다

**노선번호로 `rte_id` 를 찾는 파라미터가 없다.** 시도를 통째로 훑어야 한다
(경기 4,671개, 실측 15초). 서버는 기동 때 미리 받아 둔다 — 그러지 않으면 첫
요청에 그 15초가 얹혀 앱이 먼저 끊고, 그 구간이 **조용히 자동차 경로로 저장된다.**

같은 번호가 여러 도시에 있다. 999 는 고양(`41016048`, 대화역 순환)과
수원(`41012103`)에 있다. 출발 정류장을 지나는 노선만 받아들여 가린다.

## 좌표를 채우는 법

노선 응답에 좌표가 없어서 **이름으로 다시 물어야 한다.**

`getSttnNoList`(cityCode + nodeNm)를 쓴다 — 근접 조회(`getCrdntPrxmtSttnList`)는
반경이 고정이라(실측 17개가 상한) 500m 옆 정류장이 안 잡힌다. `cityCode` 는
근접 조회 응답의 `citycode` 에서 얻는다(고양 = `31100`).

**부분 일치가 온다.** `애니골입구` 를 물으면 `약산마을.애니골입구` 가 온다.
정규화해서 같은 것을 먼저 쓰고, 없으면 포함하는 것을 쓴다.

**같은 이름이 여럿이다.** `풍산역` 은 다섯 곳이다. 직전 정류장에서 가장 가까운
후보를 고르면 순환 노선의 상행·하행까지 갈린다.

**빈 결과를 캐시하면 안 된다.** 이 API 는 정상 요청에도 오류 봉투를 섞어 보낸다.
그때의 빈손을 기억하면 그 정류장이 영구히 빠진다 — 실제로 `애니골입구` 하나가
그렇게 사라져 경유점이 7개에서 6개가 됐다.
