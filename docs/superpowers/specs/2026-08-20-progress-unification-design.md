# 진행도를 한 벌로 — 카드와 지도의 동기화

2026-08-20 · **구현됨.** 검증 결과는 문서 끝에 있다

## 문제

"얼마나 왔나" 를 두 화면이 **각자 계산한다.**

| 화면 | 계산 |
|---|---|
| 카드의 노선도 점 | `shape.totalMeters - state.remainingMeters` (`RouteStripView.position`) |
| 지도의 지나온/남은 색 분리 | `lat/lon` 에서 폴리라인의 가장 가까운 점 (`HomecomingJourneyMap.splitIndex`) |

## 측정 (2026-08-20, 로컬 서버 + 실제 경로 28.4km)

경로 위 8개 지점을 순서대로 보고하며 두 값을 같은 축(정류장 거리)으로 환산해 견줬다.

| 상황 | 카드 | 지도 | 차이 |
|---|---|---|---|
| 정상 이동 (8지점 평균) | — | — | **36m** (최대 95m) |
| 향하는 정류장이 어긋난 경우 | — | — | **0/8** |
| GPS 역행 (60% → 45%) | 18.72km 유지 | 11.32km 로 되돌아감 | **7,404m** |
| 경로 1.5km 이탈 | 24.10km (**앞으로 튐**) | 19.76km | **4,349m** |
| 경로 복귀 | 24.75km | 24.78km | 27m |

**정상 이동에서는 이미 잘 맞는다.** 갈라지는 것은 예외 상황이다.

## 드러난 버그 (지도와 무관하게 잘못된 동작)

**경로를 벗어나면 노선도 점이 앞으로 뛴다.**

서버는 이탈하면 `remaining_meters` 를 경로 따라 재던 것에서 **집까지 직선거리**로 바꾼다
(`estimateSource: "offRoute"`). 노선도는 그것을 모르고 `totalMeters - remainingMeters` 를
그대로 계산한다. 직선거리는 작으니 "많이 왔다" 가 된다 — 실측에서 60% 지점에서 옆으로
1.5km 빠졌는데 점이 85% 로 전진했다.

`remainingMeters` 는 **뜻이 바뀌는 값**이라 위치 계산의 근거로 쓸 수 없다.

## 결정

**진행도를 서버가 한 번 계산해 내려보내고, 두 화면이 그 숫자를 쓴다. 계산은 한 벌이다.**

근거가 될 값은 이미 서버에 있다 — `sessions.route_progress`. 성질이 맞다:

- 뒤로 가지 않는다 (GPS 가 흔들려도 점이 되돌아가지 않는다)
- 이탈하면 갱신을 멈춘다 (뜻이 바뀌지 않는다)
- 경로 위에서만 정의된다

이 프로젝트가 이미 정해 둔 방침과 같다 — *"content_state 를 한 번 계산해 수신자마다
그대로 보낸다"*, *"가족 기기는 아무것도 계산하지 않는다"*(`WatchingStore` 주석).
지도가 그 원칙 밖에 있었다.

### 무엇을 어디에

| | 출처 |
|---|---|
| 노선도 점 | 서버가 준 진행도 |
| 지도의 색 분리 | 서버가 준 진행도 (**같은 값**) |
| 지도의 귀가자 점 | **실제 GPS 그대로** — 바꾸지 않는다 |

**귀가자 점을 GPS 로 두는 것이 핵심이다.** 진행도는 하나로 통일하되 실제 위치는 있는
그대로 보여준다. 그러면 이탈했을 때 이렇게 보인다 —

```
색 분리  →  60% 에서 멈춤
파란 점  →  선 밖으로 나감      ← 이것이 이탈 신호다
```

지금은 이탈을 화면에서 알 방법이 없다. 이 설계는 그것을 눈에 보이게 만든다.

## 구현

세 곳.

**1. 서버 `content_state()`** — `travelledMeters` 를 더한다.

```python
# 경로 위에서 여기까지 왔다(m). 노선도의 점과 지도의 색 분리가 이 값을 함께 쓴다.
# route_progress(초) 를 거리로 바꾼 값이고, remaining_meters 와 달리 이탈해도 뜻이
# 바뀌지 않는다 — 갱신이 멈출 뿐이다.
if session["route_id"]:
    state["travelledMeters"] = route_length(legs) - route_remaining(legs, session["route_progress"])
```

**2. `RouteStripView`** — `travelledMeters` 를 쓰고, 없으면 예전 계산으로 폴백.

```swift
// 옛 서버는 이 값을 안 보낸다. 그때는 예전처럼 남은거리로 낸다.
let travelled = state.travelledMeters ?? (shape.totalMeters - state.remainingMeters)
return shape.position(travelled: travelled)
```

**3. `HomecomingJourneyMap`** — 가장 가까운 점 대신 그 거리에서 자른다.

> **고침**: "폴리라인 누적거리" 로 쓰여 있었는데 그 축이 다르다. 이어붙인 폴리라인은
> 구간 경계의 이음(앞 구간의 끝점과 뒤 구간의 시작점이 어긋난 자리)을 포함한다 —
> 이 경로에서 세 곳에 31.8m·52.1m·14.0m, 합 **97.9m**. 서버 `route_length()` 는 구간
> 안만 재므로 폴리라인으로 견주면 그만큼 밀린다. **구간별로 누적**하면 차이가 4m 로
> 떨어진다. `CLLocation.distance` 와 서버 `haversine()` 의 차이는 6.8m 였다.
>
> 자르는 계산은 `App/Watching/RouteTrail.swift` 로 떼어 냈다. 뷰 안에 두면 앱 밖에서
> 재 볼 수 없다 — 이제 `swiftc` 로 그 파일을 그대로 컴파일해 잰다.
>
> `passedSet` 은 없애고 구간을 진행 지점에서 **둘로 쪼갠다**. 구간 단위로만 흐리게
> 하면 18.7km 지하철 구간(이 경로의 66%)을 타는 동안 색이 한 번도 안 바뀌어서,
> 카드의 점은 내려가는데 지도는 멈춰 있는 것처럼 보인다.

**4. 이탈 표시** — 지도에 한 줄. `state.estimateSource == "offRoute"` 일 때
`경로를 벗어났어요` 처럼 적는다. **안 적으면 안 된다** — 점과 색이 어긋난 이유를
화면이 설명하지 못하면 고장으로 읽힌다. 이 프로젝트가 `estimateSource` 를 만든 이유가
그것이다(*"진단값이 거짓이면 진단을 방해한다"*).

## 하지 않는 것

**지도를 카드에 맞추려고 GPS 점을 합성하지 않는다.** 이 기능의 출발점이
"귀가자의 위치를 지도로 그대로 보여주는 것" 이었다. 진행도를 통일하는 것과
위치를 꾸미는 것은 다르다.

**카드를 지도에 맞추지 않는다.** 위젯은 폴리라인을 받을 수 없다 — APNs 4KB 한도에
좌표열(5.9KB)이 안 들어가고, 라이브 액티비티 뷰는 네트워크를 쓸 수 없다.

## 구현하며 드러난 것 (2026-08-20)

**도착에서 진행도가 끝에 닿지 않는다.** `route_progress` 는 끝까지 가지 않는다 —
도착은 거리로 판정하고(`stage_for`) 그때 `remaining_meters` 만 0 으로 내린다. 그대로
보내면 두 화면이 마지막 구간을 남은 것으로 그린다. 그래서 `route_travelled()` 가
`stage == "arrived"` 면 경로 전체 길이를 준다. 화면 쪽에도 `stage.isFinished` 가드를
남겨 뒀다 — 이 필드를 모르는 옛 서버에서도 두 화면이 같이 끝에 닿아야 한다.

**로컬 갱신이 서버 값을 지운다.** `HomecomingActivityManager.update` 는 `previous`
에서 서버만 아는 값을 옮겨 담는데 `estimateSource` 가 그 목록에 없었다. 귀가자 본인
화면에서는 이탈 표시가 로컬 갱신 한 번에 사라졌을 것이다. `travelledMeters` 와 함께
옮기도록 고쳤다.

## 검증 결과

`python3 Tools/verify-progress-sync.py` — 서버(`recompute` → `content_state`)와
앱(`RouteTrail.swift` 를 `swiftc` 로 그대로 컴파일)을 실제 경로 28.4km 로 돌린 값이다.

**처음 낸 표는 잘못 잰 것이었다.** 지도 쪽 숫자로 `RouteTrail` 이 돌려준 "지나온
길이" 를 썼는데, 그건 앱이 자기 자로 잰 값이라 **요청한 거리와 같은 것이 당연하다**
— 전부 0m 로 나오고 아무것도 확인되지 않는다. 자른 **자리**를 서버가 쓰는 자
(`haversine`, 구간별 누적)로 되재야 두 화면이 같은 지점을 가리키는지 나온다.
그렇게 고친 값이다.


**남는 차이는 계산이 갈라진 것이 아니라 자가 다른 것이다.** 앱은

그 차이가 경로를 따라 쌓여 끝에서 7.0m 다 — 28.4km 의 **0.025%**. 거리에 비례해
자라므로 출발 쪽에서는 1m 안이다.

**옛 계산은 예외 상황에서 갈라진다** — GPS 역행 -7,837m, 이탈 -4,218m. 이탈 행에서
카드(옛)가 19,926 → 25,148 으로 **앞으로 뛰는 것**도 그대로 보인다. 고친 것이 그것이다.

### 축이 이 경로에만 맞는 것이 아니라는 확인

진행도를 처음부터 끝까지 옮기며(구간 경계에 정확히 떨어지는 자리도 넣어) 훑는다.

```
실제 경로 28.4km          자리 68개 · 최대 차이  7.4m
이음 200m 를 낸 경로        자리 67개 · 최대 차이 11.0m   ← 이음을 벌려도 안 밀린다
이음 1000m 를 낸 경로       자리 67개 · 최대 차이 11.0m
78m 구간 + 점 하나 구간     자리 64개 · 최대 차이 22.4m   ← 21km, 자 차이 0.107%
```

이음을 200m·1000m 로 벌려도 값이 안 변한다 — **구간별로 누적하기 때문이다.**
이어붙인 폴리라인으로 잘랐다면 여기서 그 틈만큼 밀린다. 합성 경로의 상대 오차가
큰 것(0.1~0.18%)은 그 경로들이 거의 남북 직선이라서다 — 자오선 방향에서 구면과
타원체의 차이가 가장 크다. 실제 경로처럼 방향이 섞이면 0.025% 로 떨어진다.

**7m 를 없애려면** 앱이 서버와 같은 haversine 을 쓰거나 서버가 측지선을 써야 한다.
안 했다. 화면에서 28km 경로의 7m 는 선 굵기(4pt)보다 훨씬 작고, 자를 하나 더
들이는 값이 그만큼 되지 않는다. 대신 숫자를 여기 적어 둔다 — 다음에 이 차이를
보고 놀라지 않도록.

서버 쪽 성질은 `Server/test_progress_sync.py` 가 지킨다 (10개). 이탈에서 되짚기가
앞으로 튀는 것을 시험으로 못박아 뒀다 — 되돌아가면 그 시험이 깨진다.

## 화면 확인 (2026-08-20, 실기기)

숫자만으로는 끝이 아니라서 실기기(iPhone 12 Pro Max, iOS 26.6.1)로 봤다. 폰에 저장된
**진짜 경로**(25.9km · 7구간 · 지하철 18.6km)의 좌표열을 그대로 재생했다 — 그 경로는
소유자만 읽을 수 있어(`GET /route/{id}` 는 `account_id = me`), 폰이 그 경로로 세션을
시작하게 한 뒤 가족 권한으로 `GET /session/{id}/route` 로 좌표열을 받아 재생용 경로를
다시 만들었다(구간별 소요시간만 거리 비례 추정이다. 나머지는 실제 값이다).

폰을 가족으로 붙이고 9초 간격으로 위치를 흘려 넣었다. 잠금화면 카드가 **갱신 50건**
동안 따라왔다 — 남은거리 25,950m → 324m, 구간 문구가 `국회의사당역까지` →
`환승로터리 도착` → `풍산역까지 37분 … 4분` → `아파트단지까지` → `집까지 5분` 으로
넘어갔고, 노선도의 점과 지도의 색 경계가 함께 내려갔다. **지하철 18.6km(경로의 72%)
구간에서도 색 경계가 계속 움직였다** — 구간 단위로만 흐리게 하던 때 멈춰 보였던 그 자리다.

이탈 표시는 이번에 빼기로 해서 화면으로 안 봤다. 숫자로는 위 표에서 확인했다.

### 그 과정에서 드러난 두 가지

**세션 시작 푸시에는 좌표가 없어서 가족 카드가 처음 뜰 때 지도가 없다.**
`content_state` 는 `last_lat` 이 있을 때만 좌표를 싣고, 그 값은 위치 보고에서만
채워진다(`recompute`). `SessionStartRequest` 에 좌표가 없어서 그렇다. 실제 귀가에서는
앱이 시작 직후 위치를 올리므로 1초 안에 메워지지만, 그 사이에 화면을 보면 "지도가 안
나온다" 가 된다 — 오늘 실제로 그렇게 헤맸다. 세션 시작 요청에 지금 좌표를 실으면
첫 카드부터 지도가 뜬다(와이어는 추가만).

**끝난 카드가 남아 있으면 "안 바뀐다" 로 보인다.** 도착·중지한 귀가의 카드가 화면에
남아 있고, 그 위에 새 귀가 카드가 또 뜬다. 옛 카드는 갱신을 받지 않으니 멈춰 있는데,
어느 것이 새것인지 화면이 말해 주지 않는다. 오늘 카드가 셋 겹쳐 있어서 갱신이 안 되는
것으로 20분을 잘못 짚었다. 세션 종료 푸시(`push/activity/end`)가 치우기는 한다.
