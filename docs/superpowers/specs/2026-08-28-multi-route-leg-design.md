# 한 구간에 버스 노선 여럿

2026-08-28 · **설계.** 구현 전이다

## 문제

버스 구간에 노선번호를 **하나만** 적을 수 있다(`busNo: "163"`). 그런데 같은
구간을 두 노선이 가는 경우가 있다.

```
국회의사당역.KB국민은행 → 신촌로터리
  163   staOrd 60 → 64
  6713  staOrd 28 → 32     ← 하차 기둥도 14205 로 같다
```

(2026-08-28 실측. 두 노선 다 같은 방향으로 그 구간을 간다.)

지금은 둘 중 하나만 적을 수 있고, **나머지 하나는 도착 칩에 안 나온다.**

**그게 손해인 이유는 칩이 있는 이유와 같다.** 이 칩은 *뛸까 말까* 를 정하려고
본다. 163이 12분 뒤여도 6713이 3분 뒤면 그걸 타면 되는데, 그 사실이 화면에 없다.

## 무엇을 만드나

### 편집기 — 노선 칸이 칩 목록이 된다

```
[버스 ▾]                    [노선 입력]  [🗑]
  163 ⓧ    6713 ⓧ
```

번호를 넣고 **확인(return)** 을 누르면 칩이 쌓인다. 쉼표나 공백을 쳐도 그때 쌓인다 —
쉼표로 적던 습관이 있어도 그대로 통한다. `ⓧ` 로 하나씩 지운다. 버스 구간에만 나온다
(지금과 같다).

**같은 번호를 두 번 넣으면 한 번만 쌓인다.** 두 번 물으면 한도만 태운다.

**쉼표로 적게 하는 안을 버렸다.** 자료를 보면 구분자를 써도 안전하긴 하다 — 서울
노선번호 723개에 공백도 쉼표도 없다(괄호와 하이픈만 있다: `7007-1`,
`한강버스(서부)`). 그래도 칩이 낫다 — **구분자를 배울 필요가 없고, 무엇이 등록됐는지
눈에 보이고, 하나만 지우기 쉽다.**

### 저장 — 더하기만 한다

```
busNo:  "163"              그대로 둔다. 첫 노선
busNos: ["163", "6713"]    새로 더한다
```

**둘 다 쓴다.** `busNo` 하나에 `"163,6713"` 을 욱여넣으면 옛 서버가 그 문자열로
노선을 찾다 실패해 **칩이 통째로 사라진다.** 지금처럼 둬야 옛 서버·옛 앱이 만나도
**첫 노선으로 내려앉는다** — 조용히 없어지는 것이 아니라 오늘의 동작이 된다.

읽는 쪽 규칙 — `busNos` 가 있으면 그것, 없으면 `[busNo]`.

### 서버 — 노선마다 묻고 빠른 순으로 합친다

```
163  → 18:44 · 3정류장 전
6713 → 18:39 · 1정류장 전
        ↓ 빠른 순
1번째  6713 18:39 · 1정류장 전
2번째  163  18:44 · 3정류장 전
```

`bus_arrival` 은 **안 바꾼다.** 여러 노선을 물어 합치는 함수를 하나 얹는다. 서울
(TOPIS)이든 경기(GBIS·TAGO)든 같은 모양을 돌려주므로 합치는 자리는 하나다.

**두 줄은 노선 상관없이 빠른 순 두 대다.** 노선마다 한 대씩 보여 주는 안을 버렸다 —
이 칩이 답하는 질문은 *지금 뭘 타나* 이지 *어느 노선을 볼까* 가 아니다. `163`이
3분·6분 뒤이고 `6713`이 20분 뒤면 앞의 둘을 보여 준다.

### 화면 — 둘째 줄에도 노선번호를 적는다

```
지금            🚌 163번 18:44 도착 · 3정류장 전   ↻
                   그다음 18:58 도착 · 9정류장 전

바뀌면          🚌 6713번 18:39 도착 · 1정류장 전  ↻
                🚌 163번  18:44 도착 · 3정류장 전
```

지금 둘째 줄은 `그다음` 이라고만 적는다. 같은 노선이라 번호를 다시 안 적었는데, 이제
다를 수 있으니 필요하다.

**와이어에 `busArrivalThenNo` 하나가 는다.** `ContentState` 는 **네 곳**을 같이
고쳐야 하는 자리다 — `CodingKeys` · `init(from:)` · `encode(to:)` ·
`HomecomingActivityManager.update()`. 네 번째를 빠뜨리면 **시험은 다 통과하고 화면만
빈다**(2026-08-26 에 실제로 그랬다).

**같은 노선이면 예전처럼 `그다음` 으로 적는다.** 번호를 두 번 적으면 눈이 시끄럽다.
즉 둘째 줄의 앞머리는 — 노선이 같으면 `그다음`, 다르면 `6713번` 이다.

## 안 바꾸는 것

**선 그리기.** 첫 노선(`busNo`)으로 그대로 그린다. 두 노선이 다른 길로 가도 이탈
문턱이 1,000m 라 묻힌다 — 서울 구간은 어차피 노선 자료가 없어 자동차 경로다.

**`bus_arrival` 과 `seoul_bus_arrival`.** 한 노선을 묻는 함수로 남는다. 합치는 것은
그 위에서 한다.

**15분 창과 30초 캐시.** 그대로다.

## 비용

조회가 **노선 수만큼** 는다. 30초 캐시가 그대로라 한 노선당 분당 2회, 둘이면 4회다.
승차 15분 창 안에서만 도므로 한 귀가에 노선당 최대 30회다.

## 실패했을 때

**한 노선이 실패해도 나머지는 보여 준다.** 둘 다 없으면 지금처럼 `도착 정보 아직
없음` 이다(2026-08-28 에 붙인 줄).

`busNos` 가 비었거나 없으면 `busNo` 하나로 도는 지금 동작이다.

## 시험

- `["163","6713"]` 두 값을 합쳐 **빠른 순**으로 세운다
- 한 노선이 `None` 이어도 나머지를 준다
- 둘 다 `None` 이면 `None`
- `busNos` 가 없으면 `busNo` 하나로 돈다 (옛 경로)
- 같은 노선의 두 대면 예전처럼 `그다음` 이 붙는다
- `busArrivalThenNo` 가 **네 곳을 다 지난다** — 인코딩 → 디코딩 → `update()` 왕복

**시험만으로는 모른다.** 시험 환경에 키가 없어 조회가 즉시 빠져나간다. **실기기로
봐야 한다** — 국회의사당역에서 두 줄에 다른 번호가 뜨는지.
