# `귀가` 탭을 지도와 카드로 가른다 — 설계 (2026-08-28)

지금은 지도와 카드가 한 `ScrollView` 안에 쌓여 있어 **스크롤이 불편하다.**
상단에서 `지도 | 카드` 를 갈라 지도는 스크롤 없이 통째로, 카드는 맘대로 스크롤되게 한다.

## 불편의 원인 — 손짓이 다툰다

`page(...)` 가 모든 탭을 `ScrollView` 로 두르고, `귀가` 탭은 그 안에 이렇게 쌓인다.

```
제목 + 부제                                       ~70pt
지도   containerRelativeFrame 0.72, 300…620pt    ← 드래그를 여기서 먹는다
카드   노선도 10개면 ~450pt
"내 귀가" · travelerStrip · runStatus · plannedJourney · controls
```

지도가 620pt 를 차지하고 그 안의 드래그는 지도가 가져간다(`interactionModes: [.pan, .zoom]`).
그래서 **페이지를 스크롤하려면 지도 밖 좁은 데를 잡아야 한다.** 화면이 852pt 인데
지도 하나가 620pt 니 남는 자리가 얼마 없다.

## 지금 구조에서 확인한 것

**지도는 두 곳에서 나온다.** 둘 다 `HomecomingJourneySection` 이다(지도 + 카드).

```
watchingSection      environment.watching.entries 를 **반복** — 남의 귀가, 여러 명 가능
travelerStripCard    activity.isRunning 일 때 — 내 귀가, 한 건
```

**귀가자 본인도 자기 지도를 본다.** 그 이유가 주석에 남아 있다 — *"귀가자가 보는
것은 자기 상태가 아니라 가족에게 나가고 있는 그림이다. … 좌표가 틀려도(4km 어긋난
집을 '집' 이라고 그리던 일) 본인 화면에서는 안 드러난다."*

그래서 이 설계는 **남의 귀가와 내 귀가를 함께** 다룬다. 지켜보는 사람 둘이 동시에
귀가하고 내가 귀가 중이면 지도가 세 벌이다 — 세로로 쌓으면 1,860pt다.

## 무엇을 만드나

```
제목
아빠 · 집에 15:52 도착          ← 지켜볼 것이 있을 때. 없으면 지금 부제 그대로
[ 지도 | 카드 ]                 ← 좌표가 있는 귀가가 하나라도 있을 때만

┌─ 지도 ──────────────────┐     ┌─ 카드 ──────────────────┐
│  남는 공간을 통째로        │     │  남의 카드들             │
│  **스크롤 없음**          │     │  "내 귀가"              │
│      ● 아빠              │     │  travelerStrip          │
│                ⌂ 집      │     │  runStatus              │
└─────────────────────────┘     │  plannedJourney         │
        ● ○ ○  ← 귀가자 셋       │  controls               │
                                │  (ScrollView, 지금 그대로) │
                                └─────────────────────────┘
```

### 지도 쪽

**`containerRelativeFrame` 을 없앤다.** 남는 공간을 다 쓰면 비율을 짐작할 이유가
없다. 상한 620 은 *"그 이상은 어차피 한 화면에 안 들어와서"* 둔 값이었으니 전제가
사라진다.

**이게 기록된 사고를 구조로 없앤다.** 2026-08-25 — *"지도를 열었는데 사람이 안
보였다."* 귀가자 마커는 영역의 가장자리에 있고(`region()` 이 bbox × 1.25),
지도 아래쪽이 화면 밖이라 그 잘린 띠에 들어갔다. 지도가 자기 화면을 다 쓰면
잘릴 띠가 없다.

**귀가자 여럿은 좌우 페이지다**(`TabView(.page)`, 아래 점). 세로로 쌓으면 스크롤이
돌아온다.

**좌표 없는 귀가는 페이지에서 뺀다.** `HomecomingJourneyMap` 은 좌표가 없으면 스스로
아무것도 그리지 않으므로, 그대로 두면 빈 페이지가 생긴다. 뺀 결과가 0개면 세그먼트
자체를 안 보인다.

### 부제로 올리는 값

지도만 보다가 카드로 옮기지 않아도 제일 궁금한 값이 보이게 한다. 지금 있는
`state.arrivalClockText` 를 쓴다 — 새로 만들지 않는다.

```
귀가
아빠 · 집에 15:52 도착           ← 지금 보고 있는 페이지의 귀가
귀가 과정을 가족에게 실시간으로     ← 지켜볼 것이 없을 때(지금 그대로)
```

여럿이면 **지금 넘겨 둔 페이지**의 것을 적는다. 페이지 선택을 이미 들고 있으니
값이 따라온다.

### 기본값

**볼 것이 있으면 `지도` 로 연다.** 가족이 앱을 여는 이유가 *어디쯤인가* 이고,
*얼마나 남았나* 는 잠금화면과 아일랜드에 이미 있다 — `WatchingCard` 주석이 적어 둔
판단 그대로다.

**기억하지 않는다.** 열 때마다 `지도` 다. 기억하면 어제 카드를 보고 끝낸 사람이
오늘 지도를 못 보고, 그게 이 화면이 있는 이유다.

## 안 바뀌는 것

- **다른 세 탭**(`경로`·`가족`·`설정`) — `page(...)` 의 `ScrollView` 그대로다.
- **지켜볼 것이 없을 때의 `귀가` 탭** — 세그먼트가 안 뜨고 지금처럼 카드만
  스크롤된다. 귀가를 시작하기 전 화면이 그것이다.
- **`HomecomingJourneyCard`·`HomecomingJourneyMap` 의 내용** — 그리는 것은 그대로다.
  `HomecomingJourneySection` 이 둘을 붙여 놓은 것만 푼다.
- **진행도** — 카드의 점과 지도의 색 분리는 같은 값에서 나온다. 손대지 않는다
  (`verify-progress-sync.py` 로 되짚는다).

