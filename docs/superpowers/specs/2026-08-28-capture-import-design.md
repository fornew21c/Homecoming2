# 캡처에서 경로 만들기 — 설계 (2026-08-28)

길찾기 앱의 **구간 상세** 캡처를 읽어 경로 편집기를 채운다. 지금은 경로 하나를
만드는 데 입력이 25번이다.

인계 [`HANDOFF-2026-08-28.md`](../../HANDOFF-2026-08-28.md) 의 `다음 작업 1번` 이다.

## 이 설계가 선 근거 — 먼저 재 본 것

설계를 정하기 전에 실제 캡처 세 장으로 다섯 가지를 쟀다. 그중 셋이 방향을 바꿨다.

### 1. 온디바이스 OCR 로 필요한 것이 전부 읽힌다

macOS Vision(`VNRecognizeTextRequest`, `ko-KR`)에 실제 캡처를 먹였다.
`supportedRecognitionLanguages` 에 `ko-KR` 이 있고, 배포 대상 17.2 에서 쓸 수 있다.

```
국회의사당역.KB국민은행 승차   conf 1.00      163>                 1.00
19132                        1.00          8개 정류장 이동·10분    1.00
신촌로터리 하차                1.00          경의중앙선 서강대역 승차  1.00
14205                        1.00          4개 정류장 이동 · 9분    0.30
풍산역 승차 / 20753           1.00          도보 328m. 7분         0.50
위시티1.3단지 하차 / 20796     1.00          12개 역 이동 · 31분     0.30
```

**위쪽 요약 막대는 못 쓴다** — `ㅊ 2분(표 9분 7분` 로 뭉갠다(0.30). 아래 상세 줄만
읽는다. 인계에 적힌 "요약 목록 화면은 못 쓴다" 와 같은 결론이 한 화면 안에서도
성립한다.

`usesLanguageCorrection` 은 **끈다.** 켜면 `19132`·`6713` 같은 번호를 말로 고치려
든다.

### 2. 기둥번호가 캡처에 찍혀 있다 — `seq` 차 규칙이 필요 없어졌다

인계에는 *"캡처엔 좌표가 없어 하차 후보가 둘로 남을 수 있다. 그때 `seq` 차 규칙을
넣을지 정한다"* 로 남아 있었다. **캡처에 기둥번호가 있다.**

```
19132 → ['국회의사당역.KB국민은행', 37.528479, 126.918068, '19132']   서울, 구운 표
14205 → ['신촌로터리',             37.554051, 126.935683, '14205']   서울, 구운 표
20753 → 풍산역        37.67315,  126.7872167                       경기, GBIS mobileNo
20796 → 위시티1.3단지  37.6822,   126.8108                          경기, GBIS mobileNo
```

이름만으로는 안 정해진다(실측):

```
신촌로터리       서울 표에 4건   14168 · 14169 · 14204 · 14205
풍산역          GBIS 에 9건, 그중 이름이 똑같은 기둥 넷
위시티1.3단지    GBIS 에 2건   20795 · 20796
```

**노선으로 좁혀도 안 정해진다**(실측 — 999 는 265개 기둥에 선다):

```
풍산역 + 999        9건 → 2건   20753(다음: 애니골입구) · 58271(다음: 밤가시7.8단지)
위시티1.3단지 + 999  2건 → 2건   20795(다음: 고양국제고) · 20796(다음: 위시티3.4단지)
```

길 양쪽이 끝까지 남는다. 이건 `narrow_by_route` 의 주석이 이미 적어 둔 한계다 —
*"좁혀도 길 양쪽 둘이 남는다. 어느 쪽으로 가는 차인지 적어 주면 사람이 고른다."*
**캡처의 기둥번호가 그 둘 중 하나를 짚는다. 사람이 고를 것이 없다.**

같은 주석의 다른 한 줄은 이 설계로 낡았다 — *"`정류장 번호 20753` 이라고 적어 줘도
그 번호는 기둥에 가서 봐야 아는 값이다."* 캡처에서는 안 가도 읽힌다.

### 3. 출발지 주소는 좌표로 못 바꾼다 — 그래서 안 바꾼다

캡처 첫 줄은 도로명 주소다(`서울 영등포구 의사당대로 13-2`, conf 1.00).
맥에서 둘 다 재 봤다.

```
CLGeocoder(주소)     → kCLErrorDomain error 8            실패
MKLocalSearch(주소)  → 국회의사당 · KB국민은행 · Hyundai Card Building
```

`PlaceSearch` 의 주석이 기록한 실패(`kCLErrorDomain 8`)가 **도로명 주소에서도**
그대로 난다. 그리고 검색은 근처 가게를 준다 — 2026-08-20 에 그렇게 고른 GS25 가
가족 잠금화면에 `GS25까지 9분` 으로 떴던 그 함정이다.

**출발지는 캡처에서 안 채운다.** 읽은 주소를 글자로만 밑에 적어 사람이 맞는지 보게
한다. 좌표는 지금처럼 현재 위치가 기본이고 `PlacePicker` 로 고친다.

### 4. 캡처에 둘째 노선이 없다

`6713` 은 `버스 도착정보 더보기` 안에 접혀 있다. 국회의사당역 카드에는 `163` 두 대만
보인다.

서버가 대신 찾아 줄 수 없다. **서울은 정류소별 경유노선을 못 묻는다**(`stationinfo/*`
가 401, 2026-08-27 기록). `6713` 이 사는 자리가 바로 서울(`19132`)이다.

**둘째 노선은 손으로 더한다.** 노선 칩 입력은 지난 회차에 이미 만들었고, 경로당 한
번 하는 일이다. 입력이 25번에서 1번이 된다.

### 5. 대기는 총량만 나온다

상세 줄의 시간을 다 더하면 `2+9+7+31+6+10+3 = 68분` 인데 머리글은
`14:35 → 15:52`, **77분**이다. 9분이 어디에도 안 적혀 있다.

`RouteSample` 의 실제 `퇴근길` 은 대기 구간 셋을 갖고 있다 — `163번 대기 3분` ·
`경의중앙선 대기 4분` · `999번 대기 2분`, **합 9분.** 캡처에서 비는 값과 같다.

**총량은 캡처에서 정확히 나오고, 어디에 얼마씩인지는 안 나온다.** 캡처 2의 열차
시각표(`14:47`·`14:57`)로 경의중앙 대기 4분은 계산되지만 그건 그날 그 시각의
시간표다. 매일 다른 값을 경로에 박지 않는다.

## 무엇을 만드나

### 경계 — 무엇이 폰을 떠나나

```
폰                                          서버
 캡처 3장 (PhotosPicker, 여러 장)
   ↓ Vision OCR  ko-KR + en-US
   ↓ .accurate · usesLanguageCorrection = false
 장별 줄 목록
   ↓ 주소 꼴 줄만 뺀다  ←── 출발 주소는 여기 남아 화면에만 쓰인다
   └──── POST /capture/parse ──────────────→ 겹침 접기
         {"pages": [[줄...], [줄...], [줄...]]}   문법 풀기
                                                기둥번호 → 좌표
                                                대기 균등 배분
 편집기 채움 ←──── {"steps":[...], "notes":[...]} ┘
```

**이미지는 폰을 안 떠난다.** 인계에서 정한 것이 그것이고 그대로다.

**문법은 서버에 둔다.** 처음에는 앱에 두려 했는데 근거가 약했다. 집 이름과 좌표는
**이미 서버에 있다** — `routes` 테이블의 `home_name`·`home_lat`·`home_lon` 이고,
도착 알림 문구가 그걸 읽는다(`{집이름}에 도착했어요`). 경로를 저장하면 구간
이름·노선번호·좌표열이 전부 올라간다. 캡처 줄에서 **새로 나가는 것은 출발지 주소
문자열과 화면 잡동사니뿐**이고, 주소는 앱이 뺀다.

서버에 두어서 얻는 것 셋:

1. **깨질 코드다.** 길찾기 앱이 화면을 바꾸면 문법이 깨진다. 서버면 배포 한 번,
   앱이면 재빌드·재설치다.
2. **시험이 거기 있다.** 파이썬 200개에 붙는다. 앱에 두면 파서를 만질 때마다
   실기기를 로컬 서버에 붙이게 되는데, **그때 앱 자격이 끊긴다**(2026-08-28 함정).
3. **왕복이 1회다.** 서버는 이미 `stop_search`·`narrow_by_route`·`route_stop_lists`
   를 갖고 있다. 앱이 파싱하면 정류장마다 `/stops` 왕복이 생긴다.

앱이 하는 판단은 하나뿐이다 — **주소 꼴 줄을 뺀다**(`시/도 + 구·시 + …로/길 + 번지`).
그 밖의 잡동사니(`LTE`·`80`·`국립아세안자연휴양림`)는 문법에 안 맞아 서버가 버린다.
**앱에 문법을 두 벌 두지 않는다.**

### 문법

캡처에서 실제로 읽힌 줄만 쓴다.

```
<이름> 승차                국회의사당역.KB국민은행 승차   버스 승차
<노선>선 <역> 승차          경의중앙선 서강대역 승차       지하철 승차
<이름> 하차                신촌로터리 하차               하차
<5자리 숫자>               19132 · 14205 · 20753 · 20796  바로 앞 정류장의 기둥
<번호>>                   163>  ·  999>                  승차 뒤 첫 노선
N개 정류장 이동 <구분> M분   4개 정류장 이동 · 9분          버스 구간
N개 역 이동 <구분> M분       12개 역 이동 · 31분           지하철 구간
도보 <거리>m <구분> M분      도보 328m. 7분               도보 구간
HH:MM - HH:MM             14:35 - 15:52                 총 시간
<H>시간 <M>분              1시간 17분                    총 시간(견주기용)
```

**구분자를 믿지 않는다.** 같은 자리가 장마다 `•` · `.` · `·` 로 흔들렸다
(`도보 328m • 7분` / `도보 328m. 7분`). 숫자만 잡고 사이는 느슨하게 읽는다.

**노선번호에 꺾쇠가 붙어 온다** — `163>` · `999>`. 떼고 읽는다.

### 겹침은 줄이 아니라 구간으로 접는다

줄로 접으면 안 된다. 캡처가 그걸 보여줬다 — 같은 자리를 장1은
`서강대역 2 번 출구까지` 한 줄로, 장2는 `서강대역` + `번 출구까지` 두 줄로 쪼갰다.
고정 UI(머리글 `1시간 17분`, 바닥글 `15:52 도착`)도 장마다 되풀이된다.

장별로 파싱한 뒤 **구간 단위로** 접는다. 장 N 의 앞 k 구간이 장 N-1 의 뒤 k 구간과
같은 **최대 k** 를 찾아 지운다. 같음은 `(mode, 도착이름, 분, 기둥)` 으로 본다.

겹침이 0이면 지우지 않고 `notes` 에 적는다 — *"장 2와 3이 안 이어집니다"*.
스크롤을 많이 해서 가운데를 건너뛰었을 수 있다.

### 구간 만들기

```
도보 … M분          → .walk    도착 이름은 다음 승차 줄의 이름
승차 + N개 … M분     → .bus / .subway   도착 이름은 다음 하차 줄의 이름
승차 앞              → .wait 를 넣는다
마지막 도보          → 도착은 집. 편집기(`resolvedSteps`)가 이미 그렇게 한다
```

캡처 세 장이 이렇게 풀린다.

```
도보   국회의사당역.KB국민은행    2분
대기   163번 대기               3분   ← 넣음
버스   신촌로터리    [163]       9분
도보   서강대역                 7분
대기   경의중앙선 대기           3분   ← 넣음
지하철 풍산역                   31분
도보   풍산역 정류장             6분
대기   999번 대기               3분   ← 넣음
버스   위시티1.3단지 [999]      10분
도보   집                      3분
                        총 77분 = 14:35 → 15:52
```

### 총 시간과 대기 배분

**총 시간은 두 길로 얻어 견준다** — 머리글 `14:35 - 15:52` 와 바닥글 `1시간 17분`.
어긋나면 머리글을 쓰고 `notes` 에 적는다.

```
남는분 = 총분 − 구간합
대기 = 남는분 ÷ 승차 수,  나머지는 앞쪽부터 1분씩
```

`9 ÷ 3 = 3·3·3`. 실제값 `3·4·2` 와 가깝고, 총합과 도착예정은 첫 번에 맞는다.
사람이 확인 화면에서 고칠 수 있다.

**남는분이 음수면 0 으로 두고 적는다.** 캡처가 어긋난 것이지 우리가 지어낼 값이
아니다.

### 기둥번호 → 좌표

```
서울   SEOUL_STOPS 에서 ars 로 바로 (구운 표, 호출 안 나감)
경기   이름으로 GBIS 를 찾고 ars 로 고른다
```

서버 안 함수 하나로 끝난다 — `stop_by_ars(name, ars)`. **새 엔드포인트도 새 쿼리
파라미터도 필요 없다.** 파싱이 서버에 있으니 조회도 같은 자리에서 한다.

이름이 함께 있어야 한다. 서울은 번호만으로 구운 표를 찾을 수 있지만 **경기는
GBIS 가 `keyword` 로만 답한다** — 번호로는 못 묻는다.

**못 짚으면 좌표를 비우고 `notes` 에 적는다. 채워 넣지 않는다.** 틀린 좌표가 박히면
서버가 그 자리를 지나갔는지로 구간을 판정하니 조용히 어긋난다. 이름으로 좁혀 후보가
하나면 그건 쓴다. 여럿이면 비운다 — 편집기가 그 칸을 표시하고 사람이 지도에서
찍는다. `canSave` 가 이미 저장을 막는다.

### 확인 화면 — 새 화면을 안 만든다

기존 편집기가 채워진 채로 열리고, 맨 위에 무엇을 읽었는지와 못 채운 칸 수를 적는다.
못 채운 칸은 그 자리에서 바로 고친다. **지금 쓰던 화면 그대로라 배울 것이 없다.**

```
┌─ 경로 만들기 ─────────────────────────┐
│ 캡처 3장에서 10구간을 읽었습니다              │
│ 정류장 4곳 · 노선 2개 · 대기 3곳(균등)        │
│ ⚠ 못 채운 칸 1                            │
└──────────────────────────────────────┘
이름  [ …………… ]                    ← 캡처에 없다. 사람이 친다
출발  [ 현재 위치 ]
      캡처의 출발지: 서울 영등포구 의사당대로 13-2
구간
 도보  국회의사당역.KB국민은행      2분
 대기  163번 대기                 3분
 버스  신촌로터리   [163 ⓧ][+]     9분    ← 6713 을 여기서 더한다
 …
```

## 시험

`Server/test_capture_parse.py`. 본보기는 실제 캡처의 OCR 을 그대로 뜨되 **주소 줄과
집 이름만 가려서** `Server/fixtures/capture-{1,2,3}.txt` 에 넣는다 — 이 저장소는
공개다(`RouteSample` 이 좌표를 가려 둔 것과 같은 이유). 정류장 이름과 기둥번호는
이미 인계 문서에 적혀 있어 새로 드러나는 것이 없다.

재는 것:

```
장 3개 → 구간 10개               겹침 접기
기둥 4곳이 정확한 좌표로            19132 · 14205 · 20753 · 20796
대기 3·3·3, 총 77분               배분
구분자가 · • . 로 흔들려도 같은 값     느슨한 파싱
겹침 0인 두 장 → notes 에 경고      안 이어질 때
기둥번호가 없는 줄 → 이름으로 좁힘     번호를 못 읽었을 때
좁혀도 여럿 → 좌표 비움 + notes     조용히 틀리지 않는다
```

**시험이 통과해도 화면이 될지는 모른다.** 실기기에서 캡처 세 장을 실제로 넣어
편집기가 채워지는 것을 본다 — 2026-08-28 의 `↻` 구멍이 시험 197개가 통과하는 동안
살아 있었다.

## 안 하는 것

- **`버스 도착정보 더보기` 캡처** — 둘째 노선을 자동으로 채우는 길. 후보 노선마다
  공공데이터 호출이 한 번씩 늘고(일일 한도 1,000회) 두 번째 캡처 종류를 읽는 설계가
  생긴다. 칩에 손으로 치는 것이 경로당 한 번이라 값이 안 맞는다.
- **출발지 좌표 자동 채우기** — 위에서 쟀듯 못 한다.
- **선 그리기 바꾸기** — 첫 노선으로 그리는 것 그대로다.
- **`seq` 차 규칙** — 기둥번호가 있어 필요 없어졌다.
