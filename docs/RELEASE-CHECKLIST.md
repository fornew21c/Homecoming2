# 출시 전 체크리스트

**개인 이름으로 App Store 에 낸다**는 전제로 쓴다. 2026-08-31 기준.

각 항목에 **누가 하는 일인지**와 **왜 걸리는지**를 적었다. 확인한 것은 근거를 달았다.

---

## A. 막는 것 — 이게 안 되면 못 낸다

### A1. APNs 를 production 으로 ⬜

**환경변수 하나다.** 코드는 이미 갈라져 있다.

```python
APNS_HOST = ("api.push.apple.com" if os.environ.get("HOMECOMING_APNS_ENV") == "production"
             else "api.sandbox.push.apple.com")
```

Railway 에 `HOMECOMING_APNS_ENV=production` 을 넣는다.

**놓치면 알림이 한 건도 안 간다.** App Store 로 받은 앱은 production APNs 를 쓰는데
서버가 sandbox 로 쏘면 전부 실패한다. 이 앱의 전부가 그 알림이다.

#### 그런데 「환경변수 하나」가 아니다 — 토큰이 지워진다

APNs 토큰은 **환경별로 다르다.** 지금 폰에 깔린 개발 빌드의 토큰은 sandbox 것이라
production 으로 쏘면 `BadDeviceToken` 이 온다. 그리고 서버가 그것을 **죽은 토큰으로
보고 지운다.**

```python
if "410" in output or "BadDeviceToken" in output:
    db().execute("DELETE FROM activities WHERE token = ?", (token,))
    db().execute("UPDATE accounts SET start_token = NULL WHERE start_token = ?", (token,))
    log("  죽은 토큰 폐기")
```

**되돌릴 수 없다.** sandbox 로 되돌려도 토큰이 이미 없어서 폰이 다시 등록해야 한다.

그러니 **미리 켜면 안 된다.** TestFlight 빌드로 갈아탈 때 같이 하는 일이다.

#### 더 나은 길 — 한 서버가 둘을 다 받는다

`BadDeviceToken` 이면 **지우기 전에 다른 호스트로 한 번 더 쏜다.**

```
production 으로 쏜다
  BadDeviceToken 이면 → sandbox 로 한 번 더
    그것도 실패해야 진짜 죽은 토큰
  성공한 환경을 그 토큰에 기억해 다음부터 바로 그쪽으로
```

그러면 **개발 빌드와 TestFlight 빌드가 같은 서버를 동시에 쓴다.** 갈아타는 순간의
끊김이 없고, 실기기로 개발하면서 가족은 TestFlight 로 쓰는 것도 된다. 대가는 환경이
틀린 첫 요청에 왕복이 한 번 더 나가는 것뿐이다.

**이걸 만들면 A1 이 아예 사라진다.**

#### 만들 것과 잴 것 (2026-08-31 에 설계까지 함, 구현 안 함)

```
apns_push 를 토큰별 환경으로              함수 하나
토큰 → 환경 표 (apns_hosts)               표 둘을 고치는 대신 새 표 하나
시험                                      subprocess.run 을 갈아 끼워 망 없이
배포                                      railway up. 앱은 안 건드린다
```

**시험이 갈라야 할 다섯 가지.** 여기서 `BadDeviceToken`·`410`·그 밖의 실패를
같은 것으로 다루면 안 된다 — 그게 이 작업의 전부다.

```
성공                        한 번만 쏘고 그 환경을 기억한다
BadDeviceToken              다른 주소로 한 번 더. 성공하면 기억
둘 다 BadDeviceToken         그때만 토큰을 지운다
410 Unregistered            앱이 지워진 것. 재시도 없이 바로 지운다
그 밖의 실패(타임아웃·503)    재시도도 삭제도 하지 않는다
기억한 환경이 틀려지면        다시 배운다 (앱을 다시 깔면 환경이 바뀔 수 있다)
```

마지막에서 둘째 줄이 특히 중요하다 — **망이 잠깐 끊긴 것을 죽은 토큰으로 오해하면
지운 것을 되돌릴 수 없다.** 지금 코드도 그건 지키고 있으니 그대로 둔다.

### A2. 안전귀가가 절반이다 — 결정이 필요하다 ⬜

`안심 확인` 버튼이 화면에 있는데 **서버가 그 값을 모른다.** 안 눌러도 가족에게 아무
일이 안 일어난다. `docs/API-SPEC.md` 가 `[P2]` 로 적어 뒀다.

**안전 기능이 도는 것처럼 보이는데 안 도는 것**이라, 그대로 내면 이 앱에서 가장
위험한 자리가 된다.

```
A. 서버가 맡는다   API-SPEC 의 Phase 2. 서버가 마감을 알고 넘기면 가족에게 푸시한다
B. 화면에서 뺀다   안 도는 기능을 안 보이게 한다. 나중에 A 를 붙일 때 다시 켠다
```

**둘 중 하나를 정해야 한다.** 지금 상태로 두는 것은 선택지가 아니다.

### A3. 개인정보 처리방침 URL ⬜

App Store Connect 가 URL 을 요구한다. 초안은 `docs/PRIVACY-POLICY.md` 에 있다.

남은 것 —

- **연락처 이메일** 채우기
- **위치정보법 검토** (아래 A4)
- 웹에 올리기 — 이 저장소가 공개이므로 **GitHub Pages** 로 된다
  (`설정 → Pages → main / docs`)

### A4. 위치정보법 — 신고 대상인지 확인 ⬜

**이 앱은 사용자의 위치를 제3자(가족)에게 제공한다.** 국내에서 위치정보는 별도 법의
적용을 받고 위치기반서비스사업 **신고 의무**가 있을 수 있다.

**개인 무료 앱에 그 의무가 걸리는지 나는 확답할 수 없다.** 짐작으로 넘기면 이 목록에서
가장 위험한 항목이 된다.

**방송통신위원회에 직접 묻는다.** 개인 앱에 변호사를 붙이는 것보다 이쪽이 맞고 무료다.
물을 것 셋 —

```
1. 개인이 만든 무료 앱이 위치기반서비스사업 신고 대상인가
2. 대상이면 무엇을 어디에 신고하나
3. 처리방침의 법정 기재사항이 무엇인가
```

답이 오면 처리방침에 반영한다.

## B. 해야 하는 것

### B1. Apple Developer Program 개인 등록 ⬜
연 $99. 번들 ID `com.kona.homecoming2` 를 그 계정으로 옮기거나 새로 만든다.

> `com.kona.*` 는 회사 도메인 꼴이다. **개인 명의로 낸다면 번들 ID 를 바꾸는 것이
> 맞는지 정해야 한다.** 바꾸면 지금 기기의 앱과 별개 앱이 되고 저장된 자격·경로가
> 안 넘어간다(2026-08-28 에 자격이 끊겨 경로가 사라진 것과 같은 일이 벌어진다).

### B2. 표시명 정하기 ⬜
지금 `귀가마중2` 다. `2` 는 원본 앱(`Homecoming`)과 나란히 두려고 붙인 개발용 꼬리다.
출시명으로 쓸지 정한다. `Tools/generate_project.rb` 의
`INFOPLIST_KEY_CFBundleDisplayName` 이 원본이다.

### B3. App Store Connect 입력 ⬜
```
개인정보 보호 세부정보    PrivacyInfo.xcprivacy 와 같은 내용을 화면에서 다시 고른다
                       위치(정확한 위치) · 이름 · 기기 ID · 전부 추적 아님
스크린샷                 6.7" 필수. 지도·카드·노선도가 보이는 화면
앱 설명 · 키워드 · 등급
심사 메모               가족 페어링을 심사자가 시험할 방법을 적어야 한다 (아래 B4)
```

### B4. 심사자가 시험할 방법 ⬜
**가족 페어링은 기기 두 대가 있어야 확인된다.** 심사자에게 그 방법을 줘야 한다.

- 데모 모드가 이미 있다(`-autoStartHomecoming`) — 다만 런치 인자라 심사자가 못 쓴다
- 화면에서 켤 수 있는 길이 필요한지 정한다

### B5. 버전 ⬜
`MARKETING_VERSION 1.0` · `CURRENT_PROJECT_VERSION 1`. 그대로 낼지 정한다.

## D. 나중에 봐도 되는 것

**계정 복구** — 기기 토큰뿐이라 폰을 잃으면 경로·페어링이 사라진다. 2026-08-28 에
실제로 겪었다(로컬 서버에 붙였다가 자격이 끊겼다). 사용자가 늘면 문의가 될 자리다.

**서버 규모** — Railway 단일 인스턴스 + SQLite. 동시 사용자가 늘면 봐야 한다.

**서버 로그** — 지금 이름·정류장·좌표가 로그에 찍힌다. 나 혼자 쓸 때는 문제가
아니었지만 남의 위치가 섞이면 다르다.
