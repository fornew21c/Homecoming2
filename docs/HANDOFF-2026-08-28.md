보내는 설계는 이 저장소의 결과 안 맞는다.

캡처엔 좌표가 없어 하차 후보가 둘로 남을 수 있다. 그때 `seq` 차 규칙을 넣을지
정한다. **회차 노선을 재 보고 정한다.**

## 오늘 한 일

### 한 구간에 버스 노선 여럿

설계 [`specs/2026-08-28-multi-route-leg-design.md`](superpowers/specs/2026-08-28-multi-route-leg-design.md) ·
계획 [`plans/2026-08-28-multi-route-leg.md`](superpowers/plans/2026-08-28-multi-route-leg.md)

**같은 구간을 두 노선이 간다.** 국회의사당역 → 신촌로터리를 163 과 6713 이 같이
가고, 하차 기둥도 `14205` 로 같다(실측: 163 staOrd 60→64, 6713 staOrd 28→32).

지금까지는 하나만 적을 수 있어 나머지가 칩에 안 나왔다. **그게 손해인 이유는 칩이
있는 이유와 같다** — *뛸까 말까* 를 정하려고 보는데, 163이 12분 뒤여도 6713이 3분
뒤면 그걸 타면 된다.

**두 줄은 노선 상관없이 빠른 순 두 대다.** 노선마다 한 대씩 보여 주는 안을 버렸다 —
이 칩이 답하는 질문은 *지금 뭘 타나* 이지 *어느 노선을 볼까* 가 아니다.

```
🚌 6713번 01:54 도착 · 1정류장 전   ↻
   163번  01:57 도착 · 3정류장 전
```

같은 노선의 두 대면 예전처럼 `그다음` 으로 적는다. 번호를 두 번 적으면 시끄럽다.

**실기기에서 확인했다**(세션 `4b78fe280af9`). 163 이 먼저 뜨고 6713 이 이어서 나왔다.

**저장은 더하기만 한다.**
```
busNo:  "163"              그대로 둔다. 첫 노선
busNos: ["163", "6713"]    새로 더한다
```
`busNo` 하나에 `"163,6713"` 을 욱여넣으면 옛 서버가 그 문자열로 노선을 찾다 실패해
**칩이 통째로 사라진다.** 지금처럼 둬야 옛쪽이 만나도 첫 노선으로 내려앉는다.

**편집기는 칩으로 받는다.** 번호를 치고 확인하면 쌓이고 `ⓧ` 로 지운다. 쉼표나 공백을
쳐도 쌓인다. 쉼표로 적게 하는 안을 버린 이유는 **구분자를 배울 필요가 없어서**다
(자료상으로는 안전했다 — 서울 노선번호 723개에 공백도 쉼표도 없고 괄호와 하이픈만 있다).

**선 그리기는 안 바꿨다.** 첫 노선으로 그린다.

### 전날 칩이 5분 사라진 것 — 원인 둘

2026-08-27 실귀가(세션 `5f72b2a46ba8`), 풍산역에서 999를 기다리던 중.

```
18:34:09      버스 999 도착 새로고침 → 없음        ← 칩이 사라졌다
18:34~18:39   /bus-arrival 호출이 **한 건도 없다**
18:39:06      사용자가 ↻ 를 눌러서야 돌아왔다
```

**자료가 그 순간 값을 못 줬고(막을 수 없다), 그 순간 30초 타이머가 스스로 꺼졌다
(우리 문제).** 타이머 조건이 `busArrivalNo != nil` 이라, 값이 비면 재시작하자마자
빠져나가고 **값을 되찾으려면 물어야 하는데 물지 않으니 못 되찾는다.**

`한 번이라도 떴던 세션이면 계속 묻는다` 로 바꿨다.

**실기기로 증명했다.** 자료가 또 빌 확률이 낮아서 **일부러 비웠다**
(`scratchpad/blank_server.py` — `homecoming_server` 를 import 해 `bus_arrival` 만
감싼다. 저장소는 안 건드린다).

```
08:53:52  비움
08:54:16  없음 → 칩 사라짐
08:54:49 · 08:55:21 · 08:55:52   없음인데도 33초마다 계속 물음   ← 예전엔 여기서 끊겼다
08:56:20  되돌림
08:56:26  값 → 칩이 저절로 돌아옴 (사람이 아무것도 안 눌렀다)
```

그리고 **오늘 실귀가 세션에서 같은 일이 실제로 났고 저절로 회복했다** —
`02:11:32 없음` → `02:12:07 값`, 35초.

### 창은 열렸는데 자료가 아직 없을 때

칩이 없는 것이 화면에서 세 가지로 똑같이 보였다 — 승차가 아직 멀다(정상), **버스가
아직 안 잡혔다(정상)**, 고장.

실시간 도착정보는 차가 **11~17정류장** 안에 들어와야 나온다(실측: 999 첫차 17분
뒤가 가장 먼 값이고 둘째 차는 아예 없다). 창은 15분이라 **자료보다 먼저 열린다.**
2026-08-27 에 창이 18:17 에 열렸는데 값은 18:27:39 에 왔다.

```
🚌 999번 · 도착 정보 아직 없음   ↻
```

**새 필드를 안 만들었다.** `busArrivalNo` 만 싣고 시각을 비운다 — 거짓이 아니다.
덤으로 30초 타이머가 그 번호를 보고 도니 **자료가 나오는 즉시** 채워진다.

### `없음` 의 이유를 가려 적는다

로그가 `없음` 이라고만 해서 **자료가 빈 것인지 우리가 걸러낸 것인지 구분할 수가
없었다**(이미 지난 차는 일부러 버린다). `arrival_none()` 이 셋을 가른다 —
`자료가 비었다` · `그 노선이 안 온다(오는 노선을 함께 적는다)` · `지난 차뿐이다`.

### 내가 앱 자격을 끊었다 — 그리고 되살린 방법

**실기기를 맥의 로컬 서버에 붙였더니 배포 계정과 끊겼다.**

토큰은 키체인에 **하나만** 있고 서버별이 아니다. 로컬 서버가 그 토큰을 모르니 401 을
주고, 앱은 401 을 받으면 자격을 버리고 재등록한다. 배포 서버로 돌아왔을 때는 이미
다른 계정이었다 — **저장한 경로도 가족 페어링도 안 보인다.**

```
01:33:24  기기 등록 e880109cf889     ← 새 계정. 경로 0개
```

`퇴근길` 은 옛 계정(`578982d6`) 밑에 그대로 있는데, SSH 가 막혀 배포 DB 를 직접 못
고친다. **앱에 이미 있던 `-homecomingMakeRoute` 로 되살렸다** — 화면 탭 없이 코드로
경로를 만들어 저장하는 인자다(`RouteSample`).

```bash
# RouteSample 을 실제 좌표로 잠깐 바꾼 뒤 (공개용 파일이라 커밋하지 않는다)
xcrun devicectl device process launch --terminate-existing \
  --device <UDID> com.kona.homecoming2 -- -homecomingMakeRoute
git checkout App/Route/RouteSample.swift
```

한 번에 됐고 163+6713 까지 들어간 채로 저장됐다.

**옛 계정은 배포 DB 에 유령으로 남았다.** 토큰을 아무도 모르므로 해가 되지는 않는다.

## 오늘 새로 알게 된 함정

**실기기를 로컬 서버에 붙이면 앱 자격이 끊긴다.** 토큰이 서버별이 아니라 하나여서,
로컬이 401 을 주는 순간 앱이 배포 계정을 버린다. **경로도 페어링도 사라진 것처럼
보인다.** 로컬로 시험할 거면 그 대가를 알고 하거나, 끝나고 다시 이을 각오를 한다.

**같은 값을 두 길이 읽으면 두 길을 다 고쳐야 한다.** 도착값을 읽는 길이 둘이었다 —
위치 보고(`arrival_ready`)와 새로고침(`handle_bus_arrival`). 계획이 앞의 것만
짚어서, 칩은 두 노선을 보여 주는데 **`↻` 는 163 만 새로 물었다.** 값이 틀리지는
않았지만 6713 만 뒤처졌다. 실측 로그에 163 만 찍히는 것으로 드러났다.

**갱신 타이머를 "값이 있을 때만" 으로 조건 걸지 말 것.** 값이 비는 순간 타이머가
꺼지고, 값을 되찾으려면 물어야 하는데 물지 않아 스스로 못 빠져나온다.

**`/health` 는 로그를 안 남긴다.** 폰에서 닿는지 볼 때 서버 로그만 보면 "안 닿는다"
로 오해한다. 실제로 그랬다 — **사내 Wi-Fi 에서 폰이 맥에 잘 닿는다.**
