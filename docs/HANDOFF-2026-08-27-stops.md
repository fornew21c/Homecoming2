## 오늘(오후) 한 일

### 경기도 GBIS 가 열렸다

**TAGO 에는 "노선 하나로 그 노선 정류장 전부" 라는 호출이 없다.** 정류장을 주면 거기
오는 노선이 온다 — 방향이 반대다. 그래서 이름만 있을 때 어느 기둥인지 정할 근거가
없었다(풍산역은 기둥이 넷이고 999는 둘에만 선다).

경기도 GBIS 에는 그 호출이 있다. **공공데이터포털 같은 키**를 쓰고 활용신청만 하면
된다(2026-08-27 승인, 오퍼레이션마다 일 1,000회 따로).

```
busstationservice/v2/getBusStationAroundListv2    좌표 → 주변 정류소(좌표 포함)
busstationservice/v2/getBusStationListv2          이름 → 정류소(좌표 포함)
busstationservice/v2/getBusStationViaRouteListv2  정류소 → 경유 노선
busrouteservice/v2/getBusRouteListv2              노선번호 → routeId
busrouteservice/v2/getBusRouteStationListv2       routeId → 경유정류소
busrouteservice/v2/getBusRouteLineListv2          routeId → 노선 형상(816점)
busarrivalservice/v2/getBusArrivalListv2          정류소 → 도착정보
```

**정류소 id 가 TAGO 와 같은 번호다.** TAGO `GGB219000638` = GBIS `219000638`.
접두사 `GGB` 만 붙는다(기둥 5개 표본 일치). **갈아타는 것이 아니라 덧붙일 수 있다.**

### 지도로 기둥을 찍던 일을 없앴다

경로를 만들 때 제일 무거운 것이 **지도를 확대해 정류장 기둥을 찍는 일**이었다.
풍산역은 기둥이 넷이고 지도에서는 다 똑같이 생겼다. 틀려도 저장할 때 아무 말이 없고,
나중에 도착 칩이 안 뜨는 것으로만 드러났다.

**세 겹으로 고쳤다.**

**하나 — 이름 검색이 경기도까지 본다.** 예전에는 서울 표만 봤다(`seoul_search`).
`풍산역` 을 치면 **0건**이라 편집기가 애플 지도로 떨어졌다.

**둘 — 애플 지도를 안 본다.** 애플 지도에는 버스정류장이 **시설로 없어서** 이름을
치면 근처 가게가 온다 — `신촌로터리` → 종로김밥 · 탐엔탐스 · 한솥도시락.
2026-08-20 에는 그렇게 고른 GS25 가 가족 잠금화면에 `GS25까지 9분` 으로 떴다.
정류장을 위에 두는 것으로 눌러 왔는데, **경기에서는 위가 늘 비어서 그 방어가 통하지
않았다.** 정류장이 아닌 자리(회사·건물)는 `지도에서 찍기` 로 간다.

**셋 — 노선번호로 좁히고 방향을 적는다.**

```
GET /stops?q=풍산역                8건 (하남풍산역 셋까지 섞여 온다)
GET /stops?q=풍산역&route=999      2건

  풍산역  20753 · 다음 애니골입구
  풍산역  58271 · 다음 밤가시7.8단지.광림교회
```

**기둥번호로 견준다.** 이름으로는 넷이 다 같아서 못 가른다. 기둥번호는 자료마다 같은
값을 쓴다 — 서울 `arsId`, 경기 `mobileNo`, 둘 다 **사람이 기둥에서 읽는 그 번호**다.

**노선번호는 그 구간의 것이 아닐 수 있다.** 승차 정류장은 도보 구간의 도착지라
거기에는 번호가 없다 — 없으면 다음 구간의 것을 쓴다(`boardingRouteNo(at:)`).

**좁힐 수 없으면 안 좁힌다.** 노선을 못 찾거나 하나도 안 맞으면 원래 목록을 그대로
준다. 빈 목록을 주면 아무것도 못 고른다.

### 방면을 적으려다 접었다

`종점 방면` 이 더 읽기 좋아서 시도했다. 회차점을 알아야 하는데 경기에는 `turnYn=Y`
가 있고 **서울 자료에는 표시가 없다.** 규칙으로 짚어 봤다(5개 노선) —

```
출발점에서 가장 먼 정류장     5개 중 1개만 맞음
같은 이름 쌍 사이의 창        5개 중 4개 (81번이 창 밖: 창 [45,50] 정답 53)
```

**4/5 로 맞는 규칙은 5번째 사람의 화면을 조용히 틀리게 한다.** 접었다.

`다음 정류장` 은 순서 목록의 그 다음 줄일 뿐이라 짐작이 없고, 서울과 경기가 같은
방법을 쓴다. **마지막 정류장에는 `종점` 이라고 적는다** — 빈칸은 "정보가 없다" 로
읽히는데, 종점이라는 것 자체가 고르는 데 쓰이는 정보다.

### 실귀가에서 칩이 5분간 사라졌다 — 그리고 고쳐진 것을 증명했다

2026-08-27 실귀가(세션 `5f72b2a46ba8`), 풍산역에서 999를 기다리던 중.

```
18:32~18:34   30초마다 도착값을 묻고 있었다
18:34:09      버스 999 도착 새로고침 → 없음        ← 칩이 사라졌다
18:34~18:39   /bus-arrival 호출이 **한 건도 없다**
18:39:06      사용자가 ↻ 를 눌러서야 돌아왔다
```

**둘이 겹쳤다.** 자료가 그 순간 값을 못 줬고(막을 수 없다), **그 순간 30초 타이머가
스스로 꺼졌다**(우리 문제).

```swift
.task(id: state.busArrivalNo) { guard state.busArrivalNo != nil else { return } … }
```

값이 비면 타이머가 재시작하자마자 빠져나간다. 값을 되찾으려면 물어봐야 하는데 물지
않으니 못 되찾는다. `한 번이라도 떴던 세션이면 계속 묻는다` 로 바꿨다.

**실기기로 증명했다.** 자료가 또 빌 확률이 낮아서 **일부러 비웠다** —
`scratchpad/blank_server.py` 가 `homecoming_server` 를 import 해 `bus_arrival` 만
감싼다(저장소는 안 건드린다). 파일 하나를 만들면 그때부터 `없음` 을 준다.

```
08:53:52  비움
08:54:16  없음 → 칩 사라짐
08:54:49 · 08:55:21 · 08:55:52   없음인데도 33초마다 계속 물음   ← 예전엔 여기서 끊겼다
08:56:20  되돌림
08:56:26  값 → 칩이 저절로 돌아옴 (사람이 아무것도 안 눌렀다)
```

같은 회차에서 **heartbeat 고침도 확인됐다** — 시작 08:50:32, 첫 제자리 보고
08:52:34. **2분 2초**다(고치기 전 4분).

**`없음` 의 이유도 적게 했다.** 로그가 `없음` 이라고만 해서 자료가 빈 것인지 우리가
걸러낸 것인지 구분할 수가 없었다(이미 지난 차는 일부러 버린다). `arrival_none()` 이
셋을 가른다 — `자료가 비었다` · `그 노선이 안 온다(오는 노선을 함께)` · `지난 차뿐이다`.

## 오늘 새로 알게 된 함정

**갱신 타이머를 "값이 있을 때만" 으로 조건 걸지 말 것.** 값이 비는 순간 타이머가
꺼지고, 값을 되찾으려면 물어야 하는데 물지 않아 스스로 못 빠져나온다.

**0 을 "없음" 으로 읽지 말 것.** `0정류장 전` 은 가장 중요한 값이다.

**같은 상수를 자는 시간과 거르는 문턱에 같이 쓰지 말 것.** 타이머가 재는 시작점이
언제나 조금 앞서서 첫 발화가 매번 걸러진다. 실효 간격이 두 배가 된다.

**공공데이터는 결과가 하나면 dict 로 준다.** 목록으로 오는 줄 알고 `for` 를 돌리면
키 문자열이 나온다. `gbis_rows()` · `new_style_get()` 이 같은 자로 막는다.

**번호만으로는 지역이 안 정해진다.** `271` 은 이천과 서울에, `999` 는 고양과 수원에
있다. 한쪽에서 찾았다고 멈추면 다른 쪽 사용자의 화면이 빈다.

**4/5 로 맞는 규칙은 넣지 말 것.** 5번째 사람의 화면을 조용히 틀리게 한다.

**한 경로로 검증하지 말 것.** 오늘 버그 둘이 노선 11개로 넓히자마자 나왔다.

**`railway up` 은 지금 디렉터리를 올린다.** `cd Server` 상태에서 쐈더니 `Server/` 가
루트로 올라갔다. 경로를 전부 `__file__` 기준으로 잡아서 살았지만 운이었다.
**저장소 루트에서 쏜다.**

**`--terminate-existing` 으로 앱을 재실행하면 세션이 닫힌다.** 앱이 죽는 것을 "그만"
으로 읽는 설계다. 실기기 확인 중에 그걸로 세션 하나를 끊었다.

**`log` 는 zsh 내장이다.** 폰 콘솔을 보려면 `/usr/bin/log stream --device-name …` 로
절대경로를 쓴다.

**비교할 값의 출처를 확인할 것.** `26755m 남음` 을 28.4km 와 견줘 "진행도가 튀었다"
고 했는데, 28.4km 는 공개용 시험 경로(`commute-sample.json`)의 길이지 사용자 경로가
아니었다. 실제 경로는 실측 합계 ≈26,600m — **진행도는 안 튀었다.**
