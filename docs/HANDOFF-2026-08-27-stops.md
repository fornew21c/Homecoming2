## 실주행에서 칩이 사라졌다

**증상** — 풍산역 정류장에서 999번을 기다리는 중이었다. 도착 칩이 떠 있다가
사라졌고, 다시 안 나타났다. 진행도는 `풍산역 → 풍산역 버스정류장` 도보 구간 위에
제대로 있었다. 화면에는 `4분 전 위치`.

**원인이 셋이고 서로 물려 있다.**

**하나 — 앞차가 지나면 그다음 차까지 같이 버렸다.**

```python
gone = value is not None and value["at"] < at
if gone:
    value = None          # ← thenAt 도 여기서 사라진다
```

`gone` 은 **이미 떠난 버스를 `18:42 도착` 이라고 말하지 않으려고** 둔 것이다
(2026-08-26). 그런데 그 값 안에는 `thenAt` — 아직 오지 않은 그다음 차 — 이 같이
들어 있다. 실측에서 999번이 293초·1158초 두 대로 왔다. **앞차가 지난 뒤에도 뒤차는
14분 넘게 참이다.** 재봤다 — 앞차가 1분 전에 지나고 뒤차가 14분 뒤인 값을 넣으면
`arrival_ready` 가 `None` 을 준다.

`promoted_second_bus()` 를 넣었다. 앞차가 지나면 **그다음 차가 이제 다음 차다.**
그것도 지났으면 `None` 이고, 그때는 이유를 찍는다.

**그다음의 그다음은 모른다** — 자료가 두 대까지만 준다(`coming[0]`·`coming[1]`).
그래서 승격한 값에는 `thenAt` 이 없고 둘째 줄이 사라진다. 그것이 맞다.

**둘 — 사라지면 되살릴 폴링이 같이 멈췄다.**

```swift
.task(id: state.busArrivalNo) {
    guard state.busArrivalNo != nil else { return }   // ← 칩이 없으면 안 돈다
```

서 있는 동안 갱신을 일으키는 것은 이 30초 되묻기뿐이다(`distanceFilter` 가 150m 라
제자리에서는 위치 보고가 안 나간다). 그런데 **칩이 있을 때만 돌았다.** 값이 사라지면
되살릴 길이 스스로 닫힌다.

**셋 — 새로고침 버튼이 칩 안에 있다.** `busArrivalChip` 안에 그려지므로 칩이
사라지면 버튼도 같이 사라진다. **손으로도 되살릴 수 없었다.**

셋이 겹쳐서, 남은 길은 heartbeat 뿐이었다 — 서서 기다리는 동안 2분에 한 번이고
그날은 4분이었다.

**고친 것** — `busArrivalNo` 조건을 뺐다. 이제 화면이 앞에 있는 동안 계속 되묻는다.
**창 검사는 서버가 한다**(`outside_arrival_window`). 앱은 창이 어디인지 모른다 —
경로 좌표도 구간 시각도 서버가 들고 있다. `ARRIVAL_BURST_SECONDS` 를 서버에 둔 것과
같은 이유다: **자원을 가진 쪽에서 막는다.**

`handle_bus_arrival` 에는 창 검사가 **없었다.** 사람이 누를 때만 오는 요청이라
횟수가 손가락에 묶여 있었기 때문이다. 이제 화면이 스스로 부르므로 그 묶임이 없다.
두 길(`arrival_ready` · `handle_bus_arrival`)이 `outside_arrival_window()` 한 자를
같이 쓴다 — 따로 들면 한쪽은 안 묻는데 다른 쪽은 묻는 창이 생긴다.

**셋째(버튼 자리)는 안 고쳤다.** 노선도의 줄 높이를 건드리는 일이라 화면을 보면서
정해야 한다. 하나·둘을 고치면 30초 안에 칩이 스스로 돌아오므로 급하지 않다.

**시험 182개**(177 → 182). 되돌리면 걸리는 것을 확인했다 —
`promoted_second_bus` 를 `None` 만 주게 바꾸면 `StaleArrivalTests` 하나가 깨진다.

**이 고침은 시험으로 검증되지 않는다.** 실기기에서 정류장에 서서, 앞차가 지나가는
것을 보고, 칩이 그다음 차로 바뀌는지 봐야 한다.

## 오늘(오후) 한 일

### 경기도 GBIS 가 열렸다

**TAGO 에는 "노선 하나로 그 노선 정류장 전부" 라는 호출이 없다.** 정류장을 주면 거기
오는 노선이 온다 — 방향이 반대다. 그래서 이름만 있을 때 어느 기둥인지 정할 근거가
없었다(풍산역은 기둥이 넷이고 999는 둘에만 선다).

경기도 GBIS 에는 그 호출이 있다. **공공데이터포털 같은 키**를 쓰고 활용신청만 하면
된다(2026-08-27 승인, 오퍼레이션마다 일 1,000회 따로).

```
busstationservice/v2/getBusStationAroundListv2    좌표 → 주변 정류소(좌표 포함)
busstationservice/v2/getBusStationListv2          이름 → 정류소(좌표 포함)
busstationservice/v2/getBusStationViaRouteListv2  정류소 → 경유 노선
busrouteservice/v2/getBusRouteListv2              노선번호 → routeId
busrouteservice/v2/getBusRouteStationListv2       routeId → 경유정류소
busrouteservice/v2/getBusRouteLineListv2          routeId → 노선 형상(816점)
busarrivalservice/v2/getBusArrivalListv2          정류소 → 도착정보
```

**정류소 id 가 TAGO 와 같은 번호다.** TAGO `GGB219000638` = GBIS `219000638`.
접두사 `GGB` 만 붙는다(기둥 5개 표본 일치). **갈아타는 것이 아니라 덧붙일 수 있다.**

### 지도로 기둥을 찍던 일을 없앴다

경로를 만들 때 제일 무거운 것이 **지도를 확대해 정류장 기둥을 찍는 일**이었다.
풍산역은 기둥이 넷이고 지도에서는 다 똑같이 생겼다. 틀려도 저장할 때 아무 말이 없고,
나중에 도착 칩이 안 뜨는 것으로만 드러났다.

**세 겹으로 고쳤다.**

**하나 — 이름 검색이 경기도까지 본다.** 예전에는 서울 표만 봤다(`seoul_search`).
`풍산역` 을 치면 **0건**이라 편집기가 애플 지도로 떨어졌다.

**둘 — 애플 지도를 안 본다.** 애플 지도에는 버스정류장이 **시설로 없어서** 이름을
치면 근처 가게가 온다 — `신촌로터리` → 종로김밥 · 탐엔탐스 · 한솥도시락.
2026-08-20 에는 그렇게 고른 GS25 가 가족 잠금화면에 `GS25까지 9분` 으로 떴다.
정류장을 위에 두는 것으로 눌러 왔는데, **경기에서는 위가 늘 비어서 그 방어가 통하지
않았다.** 정류장이 아닌 자리(회사·건물)는 `지도에서 찍기` 로 간다.

**셋 — 노선번호로 좁히고 방향을 적는다.**

```
GET /stops?q=풍산역                8건 (하남풍산역 셋까지 섞여 온다)
GET /stops?q=풍산역&route=999      2건

  풍산역  20753 · 다음 애니골입구
  풍산역  58271 · 다음 밤가시7.8단지.광림교회
```

**기둥번호로 견준다.** 이름으로는 넷이 다 같아서 못 가른다. 기둥번호는 자료마다 같은
값을 쓴다 — 서울 `arsId`, 경기 `mobileNo`, 둘 다 **사람이 기둥에서 읽는 그 번호**다.

**노선번호는 그 구간의 것이 아닐 수 있다.** 승차 정류장은 도보 구간의 도착지라
거기에는 번호가 없다 — 없으면 다음 구간의 것을 쓴다(`boardingRouteNo(at:)`).

**좁힐 수 없으면 안 좁힌다.** 노선을 못 찾거나 하나도 안 맞으면 원래 목록을 그대로
준다. 빈 목록을 주면 아무것도 못 고른다.

### 방면을 적으려다 접었다

`종점 방면` 이 더 읽기 좋아서 시도했다. 회차점을 알아야 하는데 경기에는 `turnYn=Y`
가 있고 **서울 자료에는 표시가 없다.** 규칙으로 짚어 봤다(5개 노선) —

```
출발점에서 가장 먼 정류장     5개 중 1개만 맞음
같은 이름 쌍 사이의 창        5개 중 4개 (81번이 창 밖: 창 [45,50] 정답 53)
```

**4/5 로 맞는 규칙은 5번째 사람의 화면을 조용히 틀리게 한다.** 접었다.

`다음 정류장` 은 순서 목록의 그 다음 줄일 뿐이라 짐작이 없고, 서울과 경기가 같은
방법을 쓴다. **마지막 정류장에는 `종점` 이라고 적는다** — 빈칸은 "정보가 없다" 로
읽히는데, 종점이라는 것 자체가 고르는 데 쓰이는 정보다.

### 실기기에서 잡은 버그 둘

**`곧 도착` 일 때 숫자가 사라졌다.** `busArrivalStopsText` 가 `stops > 0` 이라 0 을
걸렀다. 0 은 "없음" 이 아니라 **그 정류장에 지금 닿고 있다**는 뜻이다. 하필 뛸지 말지를
정해야 하는 순간에만 숫자가 없어졌다. 실측 — 163번 `staOrd 60 − sectOrd1 60 = 0`,
`arrmsg1 = 곧 도착`. **실기기에서 확인했다.**

**heartbeat 첫 발화가 매번 걸러져 실효 간격이 4분이었다.** 120초 자고 일어나
"마지막 보고가 120초보다 오래됐나" 를 물었는데, 재는 시작점이 타이머보다 뒤라
119.x초로 읽혔다.
```
고치기 전   12:49:07 시작 · 12:51 건너뜀 · 12:53:08 첫 보고    4분
고친 뒤     13:11:45 시작 · 13:11:46 첫 보고 · 13:13:47        2분 1초
```
주석이 요구한 "노선도의 3분 문턱보다 짧게" 가 깨져 있었다 — 있으나 마나가 아니라
반대로 작동했다.

**서 있는 동안의 자동 갱신은 잘 돈다.** 33초 간격으로 값이 바뀌는 것을 확인했다.

### 넓게 재서 잡은 버그 둘 — 한 경로만 봐서는 안 나왔다

사용자가 *"지금 내 경로만 확인 중이라"* 고 짚었다. 노선 11개로 다시 쟀고 둘이 나왔다.

**하나 — 결과가 하나면 목록이 아니라 dict 로 온다.** `keyword=999` 는 `busRouteList`
가 list(셋)인데 `keyword=271` 은 dict 하나다(경기도 이천시). 그대로 `for` 로 돌면
**키 문자열**이 나와서 `row.get` 이 터진다 — `/stops?…&route=271` 이 **500** 을 냈다.
`new_style_get` 은 같은 함정을 이미 막고 있었는데 GBIS 쪽 셋에서 빠뜨렸다.

**둘 — 같은 번호가 두 지역에 있으면 서울을 안 봤다.** 경기에서 찾으면 멈췄다.
`271`(이천·서울), `999`(고양·수원)가 그런 경우다.

확인한 노선 — 경기 `999 · 7770 · 1000 · 81 · 9700`, 서울 `163 · 143 · 271 · N13 ·
01A`. 전부 좁혀지고 방향이 붙는다. `6002` 만 0건인데 고른 이름이 `GS주유소(가상)` 로
공항버스 가상 정류장이라 어느 자료에도 없다 — 버그가 아니다.

### 시험이 진짜 DB 를 지우던 것

**오늘 이것으로 로컬 DB 의 `퇴근길` 이 날아갔다.**

```
DB_PATH = os.environ.get("HOMECOMING_DB", "Server/homecoming.sqlite")   ← 상대경로
```

import 할 때 한 번 정해지고 기본값이 상대경로다. `HOMECOMING_DB` 를 거는 시험이 일곱
중 셋뿐인데 **먼저 import 되는 `test_bus_arrival` 이 안 걸어서** 그쪽이 이겼다.

```
cd Server && python3 -m unittest discover   → Server/Server/homecoming.sqlite (유령 폴더)
python3 -m unittest discover -s Server      → 진짜 DB 를 지운다
```

**`rm -rf Server` 사고와 같은 뿌리다.** 그 사고도 이 유령 폴더를 치우려다 났다.

고친 것 — `default_db_path()` 로 절대경로, 시험 다섯에 가드, **가드가 빠지면 걸리는
시험 둘**. 표식 행을 넣고 양쪽에서 돌려 살아남는 것을 확인했다.

### 새로고침을 톡톡 누르면 한도가 네 배로 탄다

`/bus-arrival` 이 1초 간격으로 네 번 나갔다. **버그가 아니라 사람이 누른 것이다** —
버튼에 중복 방지가 있지만(`refreshing`) 응답이 오면 풀리는데 왕복이 1초 미만이라
1초 간격 탭을 못 막는다.

누르는 사람을 탓할 일이 아니다. 1초 만에 다시 물어도 같은 값이 온다.
**자원을 가진 서버가 막는다**(`ARRIVAL_BURST_SECONDS = 3`, 실측 근거: 정류장 수가
약 57초에 하나씩 줄었다).

### 칩이 왜 없는지 말하게 했다

칩이 안 뜨는 것은 정상일 때가 많다(승차가 아직 멀다). 문제는 **고장일 때도 화면이
똑같다**는 것이다. `arrival_says()` 가 세 갈래를 각각 말한다. 이유가 바뀔 때만 찍는다.

### 서울 시군구 훑기가 끝났다

`getBusStop` 에 11000~11999 를 전부 넣었다. **하나도 안 나온다.** TAGO 도시코드
목록에 서울이 아예 없다는 것과 맞는 결과다. `Tools/sgg-sweep.py` 가 이제 요청을
0회 쓰고 끝난다.

## 오늘 새로 알게 된 함정

**0 을 "없음" 으로 읽지 말 것.** `0정류장 전` 은 가장 중요한 값이다.

**같은 상수를 자는 시간과 거르는 문턱에 같이 쓰지 말 것.** 타이머가 재는 시작점이
언제나 조금 앞서서 첫 발화가 매번 걸러진다. 실효 간격이 두 배가 된다.

**공공데이터는 결과가 하나면 dict 로 준다.** 목록으로 오는 줄 알고 `for` 를 돌리면
키 문자열이 나온다. `gbis_rows()` · `new_style_get()` 이 같은 자로 막는다.

**번호만으로는 지역이 안 정해진다.** `271` 은 이천과 서울에, `999` 는 고양과 수원에
있다. 한쪽에서 찾았다고 멈추면 다른 쪽 사용자의 화면이 빈다.

**4/5 로 맞는 규칙은 넣지 말 것.** 5번째 사람의 화면을 조용히 틀리게 한다.

**틀린 값을 안 그리려고 버릴 때, 같이 버려지는 참값이 있는지 볼 것.** `gone` 이
지나간 앞차를 지우면서 아직 오지 않은 뒷차를 같이 지웠다. 하필 앞차를 놓친 순간이
"다음 차 언제 오나" 가 가장 궁금한 순간이다.

**값이 사라졌을 때 되살릴 길이 그 값에 매여 있으면 안 된다.** 30초 되묻기가
`busArrivalNo != nil` 일 때만 돌았고, 새로고침 버튼은 칩 안에 있었다. 칩이 사라지자
둘 다 같이 사라져서 되살릴 방법이 없었다.

**한 경로로 검증하지 말 것.** 오늘 버그 둘이 노선 11개로 넓히자마자 나왔다.

**`railway up` 은 지금 디렉터리를 올린다.** `cd Server` 상태에서 쐈더니 `Server/` 가
루트로 올라갔다. 경로를 전부 `__file__` 기준으로 잡아서 살았지만 운이었다.
**저장소 루트에서 쏜다.**

**`--terminate-existing` 으로 앱을 재실행하면 세션이 닫힌다.** 앱이 죽는 것을 "그만"
으로 읽는 설계다. 실기기 확인 중에 그걸로 세션 하나를 끊었다.

**`log` 는 zsh 내장이다.** 폰 콘솔을 보려면 `/usr/bin/log stream --device-name …` 로
절대경로를 쓴다.

**비교할 값의 출처를 확인할 것.** `26755m 남음` 을 28.4km 와 견줘 "진행도가 튀었다"
고 했는데, 28.4km 는 공개용 시험 경로(`commute-sample.json`)의 길이지 사용자 경로가
아니었다. 실제 경로는 실측 합계 ≈26,600m — **진행도는 안 튀었다.**
