## 다음 작업, 순서대로

**1. 지도 카메라가 굳는지 확인 (미해결, 가장 앞)**
이탈 화면을 실기기에서 보는데 지도가 **출발 쪽(여의도)에 머물러 있었다.** 그 프레임에는
귀가자도 집도 남은 경로도 없었다. 그때 서버가 보낸 상태에는 좌표·집·반경이 다 있었으니
값 문제가 아니다. 카드를 새로 띄운 뒤(연결을 다시 맺으면 지금 상태로 카드가 다시 뜬다)
지도가 귀가자·집을 담는지 보면 갈린다 —
- 담으면: 그때 프레임이 한 번 어긋난 것. `HomecomingJourneyMap` 의
  `.onChange(of: TravelerFrame…)` 이 갱신마다 도는지만 확인하면 된다
- 여전히 출발 쪽이면: 카메라가 굳은 것. `camera` 는 `@State` 이고 `.onAppear` 와
  `.onChange` 두 곳에서만 바뀐다. 갱신이 뷰까지 오는데 카메라만 안 움직이는 경로를 찾는다

**2. 버스 시군구 코드 마무리** — `launchd` 가 알아서 훑고 있다(아래 "걸어 둔 것").
결과 파일이 채워지면 `BUS_SGG` 에 넣고, **새로 커버되는 도시의 실제 노선으로 경유정류장이
오는지 한 번 검증한다.** 코드가 `getBusStop` 에 있다는 것이 경유정류장 API 에서도 된다는
뜻은 아니다. 방법과 한도 규율은 `docs/BUS-API.md`.

**3. 배포 DB 의 검증용 계정** — 오늘 여러 개 늘었다. 계정 삭제 엔드포인트가 없다.
서버에 정리 기능을 만들지, 그냥 둘지 결정이 필요하다(위치 이력은 세션이 끝날 때 지워지므로
남는 것은 계정 행과 시험용 경로뿐이다).

**4. 화면으로 아직 안 본 것** — `경로 없이` 소요시간 입력(`경로` 탭), `귀가` 탭의 이번 귀가
요약(대기 중일 때만 나온다), 버스 노선 자료 없을 때의 편집기 안내.

## 오늘 한 일

**진행도를 한 벌로** — 카드의 노선도와 지도의 색 분리가 서버가 준 `travelledMeters` 하나를
쓴다. 실제 경로 28.4km 로 재서 두 화면 차이는 **끝에서 7m**(자 차이 — 앱 측지선 · 서버 구),
GPS 역행·이탈·복귀에서도 붙어 있다. 옛 계산은 같은 자리에서 7.8km·4.2km 갈라졌다.
실기기에서 잠금화면이 갱신 50건 동안 25,950m → 324m 로 따라오는 것까지 봤다.
자세한 것은 [설계문서](superpowers/specs/2026-08-20-progress-unification-design.md).

**경로 없이 귀가하기 — 앱까지 끝** — `plannedMinutes` 를 보내고, `RouteCard` 의 `경로 없이`
아래에서 적고(20·30·45·60·90분 + 5분 조정, 도착 시각 표시), 시작 가드가
`canStartWithoutRoute` 를 실제로 쓴다. 경로 목록이 비어도 그 줄을 그린다.

**거리가 부정확했던 것 셋** — 실주행에서 드러났다.
- 카드에 **직선거리로는 나올 수 없는 값**이 뜬 것은 서버 `/eta` 의 **직선×1.35** 였다.
  경로 없는 귀가에서 앱이 언제나 직선을 쓰도록 고쳤다(시작·ETA 재계산 양쪽)
- **진행 바가 0 에 붙는 것** — 분모가 출발 시점 직선거리로 박혀 있었다. `widen_total` 이
  넓힌다(줄이지는 않는다)
- **일산에서 짧게 나온 것** — `pollLocation` 이 나이를 안 보고 낡은 픽스를 즉시 돌려줬다.
  이제 낡으면 시작을 거절한다("위치를 아직 못 잡았습니다")
- **두 번 누른 것이 영향을 줬다** — 경로 없는 귀가는 `routeId` 만 견줘 6시간 안의 세션을
  이어 썼다. `same_journey` 가 출발지도 본다(문턱은 `stage_for` 의 `nearby`)

**가족 카드가 처음부터 지도를 그린다** — 세션 시작 요청에 출발 좌표를 싣는다. 예전에는 첫
카드에 좌표가 없어 지도가 없었다(1초 뒤 메워지지만 그 사이를 보면 고장으로 읽힌다).

**지도 가독성** — 지나온 길 회색 3pt / 남은 길 상태색 5pt(색상으로 가른다. 진하기만
다르면 도로에 묻힌다), 도보는 동그란 점 3.5pt, 높이는 보이는 높이의 46%(300~460pt).

**집은 하나다** — `/route` 목록이 경로의 집 좌표를 함께 주고, 지금 집에서 도착 반경보다
멀면 `RouteCard` 가 그 줄에 적는다(그 경로로는 도착 판정이 안 떨어진다).

**조용한 폴백 제거** — 버스 노선 자료가 없으면 자동차 경로로 그리는데 로그조차 없었다.
`RouteTracer.plot` 이 `Plotted`(legs + busFallbacks)를 돌려주고, 편집기가 저장 후 창을
닫지 않고 노선번호를 적어 준다.

**경로를 기기 사이로 옮기는 도구** — `-homecomingDumpRoute <id|이름>` /
`-homecomingImportRoute <base64>`. 계정은 기기를 넘지 않는다(키체인 `ThisDeviceOnly`).
가족 권한으로 받는 좌표열에는 **구간별 소요시간이 없다** — 실측 차이가 드러났다(추정 버스
11분·지하철 40분 vs 진짜 16분·37분).

**정리** — 주석의 "퇴근" 12곳을 `귀가` 로(문장마다 골랐다), `ContentView.header` 죽은 코드

## 오늘 새로 알게 된 함정

**공공데이터 일일 요청 한도가 1,000회다.** 시군구 코드를 동시 4개로 훑다가 하루치를 다
써서 그날 서버의 버스 노선 조회까지 종일 막혔다(`429` · 코드 22). 훑기 전에 한도를 본다.

**`POST /route` 는 같은 이름이면 덮어쓴다(id 유지).** "새로 저장한 뒤 옛 사본 삭제" 를
하면 방금 올린 것을 지운다. 두 번 그랬다.

**`-homecomingHome <lat,lon>` 은 그 기기의 집 설정을 덮어쓴다.** 검증하려고 넘기면
사용자가 지정해 둔 집이 조용히 바뀐다.

**앱을 다시 설치하면 라이브 액티비티가 지워진다.** 세션은 서버에 남으므로, 연결을 다시
맺으면 그 시점 상태로 카드가 다시 뜬다(`/pair/accept` 가 귀가 중이면 카드를 띄운다).

**끝난 카드가 남아 있으면 "갱신이 안 된다" 로 보인다.** 도착·중지한 카드 위에 새 카드가
또 뜨고, 옛 카드는 갱신을 받지 않는다. 이것으로 20분을 잘못 짚었다.

**시뮬레이터는 push-to-start 는 받지만 갱신 토큰을 주지 않는다.** 그리고
`CODE_SIGNING_ALLOWED=NO` 로 빌드하면 `aps-environment` 엔타이틀먼트가 빠져 푸시 토큰이
아예 안 나온다(생성 스크립트 주석이 경고하고 있었다). 시뮬레이터 검증은 ad-hoc 서명으로.

**`devicectl` 에 앱 인자를 넘길 때는 `--` 로 가른다.** 안 그러면 `-homecomingListActivities`
같은 이름이 짧은 옵션 묶음으로 읽혀 `-t` 값 없음 오류가 난다.

**`log stream --device` 가 이 macOS 에 없다.** 실기기 로그를 맥에서 스트리밍할 수 없고,
`osascript` 는 접근성 권한이 없어 시뮬레이터 창도 못 누른다. 실기기 화면 확인은 사람 눈이
필요하다.
