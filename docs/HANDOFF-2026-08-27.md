## 오늘 한 일

### 서울 버스 도착이 된다

**전날에는 "서울은 안 된다" 로 닫았는데 그게 성급했다.** 조각 셋 중 둘은 이미
있었다.

```
정류장 arsId       seoul-stops.json 에 이미 있다      ✅
도착정보 호출       TOPIS arrive/* 는 지금 키로 열림    ✅
노선번호 → 노선id   busRouteInfo/* 가 401             ❌
```

TOPIS 는 **서비스마다 따로 신청받는다.** `버스도착정보조회` 만 승인돼 있어서
`arrive/*` 는 되고 `stationinfo/*` · `busRouteInfo/*` 는 401 이다. 401 을 하나
보고 "서울 전체가 막혔다" 로 읽은 것이 잘못이었다.

막힌 하나는 **표로 받아 풀었다.** 서울 열린데이터광장에 노선번호와 id 가 짝지어진
파일이 있고 **신청도 인증키도 필요 없다** — 정류장 표를 같은 이유로 같은 곳에서
받고 있다.

```
python3 Tools/seoul-routes.py ~/Downloads/서울시버스노선ID정보*.xlsx
  → Server/data/seoul-routes.json   노선 723개, 16KB
  163: 100100032 · 6713: 100100293
```

**글자를 파싱하지 않는다.** `arrmsg1` 은 `곧 도착` · `6분17초후[1번째 전]` 같은
문자열인데, 같은 항목에 숫자가 그대로 온다.

```
traTime1 = 85              초. `곧 도착` 일 때도 숫자는 있다
staOrd − sectOrd1 = 0      몇 정류장 전
```

그래서 **TAGO 와 값 모양이 같아진다.** `bus_arrival` 이 정류장을 못 찾으면
`seoul_bus_arrival` 로 넘기고, 앱과 화면은 **한 줄도 안 고쳤다** — 절대시각,
15분 창, 배경 갱신, 지나간 시각 자르기, 두 줄 칩, 새로고침이 그대로 돈다.

**정류장을 노선 안에서 고른다.** 한 번 부르면 그 노선 정류장이 다 오므로 그중
승차 좌표에 가장 가까운 것을 쓴다 — **노선이 안 서는 기둥을 고를 수가 없다.**
TAGO 쪽(`arrival_stop`)이 노선을 모른 채 가장 가까운 기둥을 골라야 하는 것과 다르다.

실측(2026-08-27 08:31):
```
서울 163    08:32 도착 · 0정류장 전   | 그다음 08:36 · 1정류장 전   (2.0초)
서울 6713   08:42 도착 · 2정류장 전   | 그다음 08:51 · 6정류장 전   (0.8초)
고양 999    08:50 도착 · 10정류장 전                              (2.5초)
```

### 서 있는 동안에도 스스로 갱신된다

**갱신의 유일한 계기가 위치 보고였다.** `update_activities` 를 부르는 곳이
`handle_location` 하나뿐이고, 그 보고는 **150m 를 움직여야** 나간다. 주기적으로
미는 장치는 서버에도 없다(배경 스레드는 한 시간마다 옛 기록을 지운다).

정류장에서 버스를 기다리는 시간이 정확히 그 상태이고, **하필 그때 이 값을 본다.**

화면이 앞에 있는 동안, **칩이 떠 있을 때만** 30초마다 다시 묻는다.
`busArrivalNo` 가 없으면 물어도 나올 것이 없고, 그러면 승차 15분 전이 아닌
내내 공공데이터를 태운다. 첫 값은 걸어가는 동안 위치 보고가 가져온다.

시뮬레이터에서 위치를 안 움직이고 확인:
```
08:49:13 → 09:07:35 도착
08:49:46 → 09:08:10
08:50:20 → 09:08:43
앱이 부른 횟수 = 서버가 받은 횟수
```

## 오늘 새로 알게 된 함정

**401 하나로 서비스 전체를 닫힌 것으로 읽지 말 것.** TOPIS 는 서비스마다 따로
승인되고, `arrive/*` 는 되는데 `stationinfo/*` 는 401 이었다. 오퍼레이션별로 재야 한다.

**TAGO 도시코드 목록에 서울이 아예 없다.** 고양은 31100 으로 있다. 그래서 서울은
좌표로 물어도, 정류장 id 로 물어도 빈 결과다 — 코드를 잘못 넣은 것이 아니다.

**`BUS_SGG` 에 서울(11)이 없어서 서울 노선의 경유 정류장을 못 찾고 있었다.**
`ctpv_cd=11` 과 서울 시군구 코드를 넣으면 나온다(163번 114개, 국회의사당·신촌로터리
포함). **다만 지금은 이득이 없다** — 저장된 163 구간(자동차 경로)에서 실제 정류장이
최대 **124m** 밖에 안 벌어진다. 이탈 문턱 1,000m 의 8분의 1이다. 시내버스는 도로를
따라가므로 지하철(1,994m)과 성격이 다르다. **고치기 전에 재 볼 것.**

**응답 봉투가 `{"Response": …}` 대문자 R 이다**(`BusRoutespecificStopInformation`).
소문자로 읽으면 조용히 빈 결과가 된다 — 그렇게 한 번 "서울은 없다" 로 잘못 결론냈다.
서버의 `new_style_get` 은 제대로 읽는다.

**`rm -rf Server` 를 쓰지 말 것.** 시험이 만드는 `Server/Server/` 를 치우려고
붙여 왔는데, 그건 `cd Server` 가 성공했을 때만 맞는 상대경로다. `&&` 사슬이 앞에서
끊기면 `;` 뒤의 삭제만 **루트에서** 돌아 진짜 `Server/` 를 지운다. 실제로 그랬다.

되돌린 것 — 추적 파일 전부(`git restore`).
영구히 잃은 것 — `Server/homecoming.sqlite`(로컬 시험 DB). 배포 DB 는 Railway
볼륨이라 안 닿았다.
다시 만든 것 — `Server/data/seoul-routes.json`(엑셀에서), `Server/.env.local`.
**`.env.local` 은 원래 비어 있지 않은 줄이 2개였는데 1개(TAGO 키)만 되살렸다.**
동작 차이는 안 보이지만 한 번 확인이 필요하다.

**절대경로로만 지운다.**
```bash
rm -rf /절대/경로/Server/Server
```
